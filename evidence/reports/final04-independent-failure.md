# final04 N03 독립 질문 — 실패 보존

새 독립 입력 N03는 학생 제출 1회에서 내부 모델 생성 2회가 실행됐고, 수업에 도달하지 못했다. 예정된 보충 1회는 NOT_REACHED다. 계획 질문2 중 실제 설명 도달0/2이며, 제출된 초기 질문만 보면 0/1이다. 성공 문항을 골라 분모를 줄이지 않는다. 새 독립 표본은 수업1개뿐이므로 일반 정확도로 해석하지 않는다.

원문은 reading이 **0 이상 4 미만**이고 stage가 hold가 아닌 행을 요구했다. 두 모델 시도 모두 `reading > 0 AND reading < 4`로 0을 누락하고 stage 조건을 빼었다. 원시 SQL의 결과도 독립 SQLite 정답과 다르다. 원시 설명은 NULL인 mica와 상한4인 wisp를 포함하며 nova를 빼는 등 SQL·원문과 모순된다.

출력 형식도 SQL 객체를 먼저 닫은 뒤 explanation 키를 객체 밖에 붙인 잘못된 JSON이었다. 앱은 명확한 후보 추출 실패로 `stopped/invalid_candidate_or_mismatch`를 기록했고, 잘못된 설명을 음성으로 읽지 않았다. 독립 검사기가 SQL 부분 객체를 사후 진단용으로 추출할 수 있다는 것과 제품이 후보를 받아들였다는 것은 다르다. 단순 파서만 완화하면 정답이 되는 사례가 아니며 의미 오류가 따로 남는다.

| 항목 | 결과 |
|---|---|
| 초기 원시 SQL 의도·결과 | 0/1 (내부 시도2 모두 오류) |
| 초기 앱 정답/실제 설명 | 0/1 |
| 예정 보충 | 제출0, NOT_REACHED1 |
| 동결 요구9개 | 초기4 미전달, 보충5 NOT_REACHED, 완전 통과0/9 |
| 새 음성·실제 설명 화면 | 없음 |
| API 검증/보류 경로 완료 | 49.453초; 첫 설명 시간으로 사용 금지 |
| 사람 교육·청취 | H_PENDING |

유효 파일은 `independent-final04-assessment-v2.json`, `independent-final04-adjudication-v2.json`이다. 입력·정답·동결 해시와 실제 두 모델 시도, 질문 원문·원시 답변은 해당 파일 및 `student/repair-independent-final04/N03/actual.json`에 보존했다. 전체 앱 판정은 NOT_READY다. N01/N02 개발 회귀와 점수를 합치지 않는다. 후속 코드 변경 후 같은 N03를 재사용하면 개발 회귀로 표시해야 한다.
