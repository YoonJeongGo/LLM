# final04 개발 회귀 사후 판정

유효한 결과는 `development-final04-assessment-v2.json`과 `development-final04-adjudication-v2.json`이다. 최초 실패 뒤 제품이 수정된 N01/N02이므로 새 독립 정확도라고 부르지 않는다. 실제 수업은 두 초기 질문과 두 보충 질문 모두 재생에 도달했지만, 요청한 정렬 설명 두 항목은 아직 부분 충족이다. NOT_READY/H_PENDING을 유지한다.

| 기준 | 실제 결과 | 범위 |
|---|---:|---|
| 원시 모델 SQL 의도와 결과 | 2/4 | N01 초기·보충 통과. N02 초기·보충 실패 |
| 앱 검증·교정 SQL 의도와 결과 | 4/4 | 독립 원본 의도·SQLite 결과 대조 |
| 지문 연결된 실제 설명 도달 | 4/4 | PCM·native 재생·대사·판서 연결, 청취 판단 아님 |
| 대사/판서의 동결 요구 완전 충족 | 14/16 | 부분 충족은 통과에서 제외 |
| 보충 후 기계적 복귀 | 2/2 | 단계·판서·셀·음성 위치 및 보충 자연 종료 |
| 전체 요구사항 검증 통과 | 16/18 | 위 내용 기준16+복귀2. 제품 완성도/일반 교육 정확도 비율 아님 |
| 질문별 모든 요구 완전 충족 | 2/4 | 초기2 통과, 보충2는 정렬 설명 부분 충족 |

N01 초기 원시 SQL은 올바르다. 보충 원시 SQL도 올바르지만 원시 설명은 P1(NULL, rush1)과 P6(0, rush1)을 제외한다고 잘못 말한다. 앱의 실제 대사는 OR에서 rush=1이 TRUE여서 둘 다 포함된다고 설명한다. P3(-4,rush0)의 포함 이유, P2(0,rush0)의 제외 이유도 같은 원본 행을 사용해 올바르게 판서하고 읽었다.

N02 초기 원시 SQL `qty IN (0,5)`는 질문의 `qty=0 OR qty>=5`와 다르다. 이번 표에는 5 초과값이 없어 결과가 우연히 같지만, 별도 가상 경계 반례 qty=6에서 다르므로 원시 정답으로 인정하지 않았다. 보충 원시 SQL은 해당 수량 조건 전체를 누락한다. 앱은 원문 의도에서 만든 조건으로 교정한 뒤 M1의 포함, M2 NULL의 제외, M7의 qty0·status hold 제외를 설명했다. 별도 빈 입력이라는 표시와 함께 SUM(qty)=NULL, COUNT(qty)=0, COUNT(*)=0을 말하고 판서했다.

남은 내용 문제는 보충 정렬이다. N01 s6은 세 키 순서와 P3의 5번째 위치를 설명하지만 동결 기준에 포함된 NULL DESC 위치 및 현재 완전 동점 없음까지 설명하지 않는다. N02 s8도 세 키 순서와 M1의 3번째 위치만 설명하고, M3/M4와 M1/M8에서 같은 앞 두 키 뒤의 item 값을 직접 비교하지 않는다. 대사·판서에 잘못된 계산을 발견한 사례와 요청한 설명이 빠진 사례를 구분한다.

N01 동일 보충 2회차는 별도 반복 안정성 1건이다. 두 cycle 모두 원래 내용 있는 표·선택 셀·단계·재생 위치로 복귀했고 보충은 자연 종료했다. 반복 1건의 원시 SQL은 맞지만 같은 잘못된 원시 설명이 다시 생성됐으며 앱은 검증된 대사를 다시 사용했다. 내용 기준은 같은 정렬 누락 때문에 4/5, 복귀1/1이다. 기본 4질문·18기준 분모에는 넣지 않았다.

실제 손/화살표 위치의 전 재생 구간 정확성은 별도 화면 검사의 대상이다. 첫 재생 연결이 통과했다는 이유로 그 후의 손동작까지 통과시키지 않는다. final04 이후 취소 UI·포인터·정렬 대사 수정 결과는 별도 빌드/회귀로 기록해야 한다. 사람의 교육·청취 검토는 하지 않았다.

## 보존 및 도구 정정

- 최초 독립 final02의 두 수업 실패는 그대로 보존했다.
- 원래 final04 `report-20261030T123749606988Z`는 보존했다. 최초 새 합성이 후속 캐시 확인으로 캐시처럼 분류된 수집기 오류를 고쳐 `report-20261030T124511994292Z`를 사용했다. 모델 재실행이 아니라 기존 파일의 분류 정정이다.
- `development-final04-adjudication.json` 초안의 집계는 무효다. 판정 문자열 접미사 검사 때문에 PARTIAL_NOT_FULL_PASS까지 통과로 세었다. v2는 명시적인 두 통과 상태만 세어 16/18이며, 요구별 실제 판단·원문은 변하지 않았다. 최초 초안·수집기·실행 실패를 성공 기록으로 덮어쓰지 않았다.

질문·답변 원문, 모든 단계 대사·판서, 실제 화면·음성 위치는 v2 assessment의 source/cases/lineage 및 수집기 gallery에 연결돼 있다.
