2026-10-29 기록 기준. 원본33개 파일과 해시를 대조했으며 생산 코드·평가 결과·장부·승인·docs·STATUS를 변경하지 않았다. 상세 수치와 출처 해시는 final-evaluation-facts.json에 있다.

## 현재 최종 빌드에서 확인한 범위

새 r3 지원20문항의 앱 실질 응답은 **19/20**, 응답한 SQL 구조·값 일치는 **19/19**다. 원시 모델 정답은 **18/20**이며 앱이 누락된 집계1개를 원문에서 별도 재구성했다. 이 수치는 확정된 단일 표와 명확한 한국어 절 문법을 사용한 개발 검증 질문의 결과다. 사진·음성·화면·중간 질문 복귀·사람의 교육 검토는 이 28문항 실행에 포함하지 않았다.

근거: base 개발 회귀, adapter1 개발 회귀. 과거 원시 채점은 각 기록의 `source_raw_result`와 같은 폴더의 `result-normalized.json`이다.

## 실제 신규 독립 평가 — 라운드별 별도 분모

각 라운드는 지원20+경계8 질문을 실제 모델과 앱에서 한 번씩 실행했다. 경계 분류4개와 CPU 오류 주입4개는 별도 분모다. 오류 주입은 실제 모델이 생성한 오류로 세지 않는다. 문항과 코드가 달라 라운드 간 차이를 통제된 정확도·속도 개선율로 해석하지 않는다.

| 실제 독립 라운드 | 원시 첫 SQL 구조·값 정답 | 앱 실질 응답 | 응답한 구조·값 일치 | 앱 보정 | 누락/미지원 분류 | 별도 CPU 오류 주입 |
|---|---:|---:|---:|---:|---:|---:|
| r1 | 19/20 | 0/20 | 정의 불가(응답0) | 0개 | 2/4 | 0/4 |
| r2 | 18/20 | 18/20 | 18/18 | 0개 | 3/4 | 2/4 |
| r3 최종 빌드 | 18/20 | 19/20 | 19/19 | 1개 | 3/4 | 2/4 |

원본 채점: r1, r2, r3.

실패 이후의 저장 답변 재처리는 위 표를 덮어쓰지 않았다. r1 저장 답변의 수정 후 개발 회귀는19/20이며, r2 저장 **첫 답변**은20/20, 저장 **마지막 보정 답변**은19/20이다. r2 마지막 11번의 추가 JSON 객체를 계속 거부한 결과다. 이 수치들은 새 독립 평가가 아니고 새 모델 호출도 없다.

## 원시 설명 감사 — 자동 주장0은 설명 오류0이 아님

- 저장된 최종 답변 **28/28**에 자동 검사 기록이 있고 **22개**에 실행 근거가 있다.
- 자동 비교가 가능한 결과 배열 **0개**, 집계 스칼라 **0개**가 파싱됐다. 전체 자유 설명을 완전 채점한 답변도 **0개**다.
- 원시 설명의 구체적 반례 **최소3개**를 저장 근거와 대조했다. 이는 전체28개를 완전 검토한 오류율3/28이 아니다.
- 12번(지원 문항): 통과 행이12행이라고 했지만 실제는5행이다. 앱은 잘못된 원시 대사를 쓰지 않고 검증된 계산을 사용했다.
- 27번(경계): COUNT(units)에 NULL이 포함되면 NULL을 반환한다고 잘못 말했다. 수업은 차단됐다.
- 28번(경계): 빈 입력의 SUM(fee)가0이라고 잘못 말했다. 실제는NULL이며 수업은 차단됐다.

위 반례 대조는 에이전트의 저장 근거 확인이며 사람의 교육·청취 검토가 아니다. **H_PENDING**을 유지한다. r3 오류 주입2/4는 SQL 불일치2개를 보존·교정한 통과이며, 설명 모순2개는 추가 설명 요청에서 검증 경로에 도달하지 못한 실패다.
