# 새 독립 질문 최초 실행 평가

대상은 `student/repair-new-final02`의 N01/N02 최초 실제 출력이며, 제품·질문·원시 답변은 바꾸지 않았다. 최종 유효 수집 결과는 `independent-final02-assessment-v3.json`, 실제 문장·SQL 사후 판정은 `independent-final02-adjudication.json`이다. 이는 AI의 기록 대조이며 사람의 교육·청취 검토는 **H_PENDING**이다.

**새 첫 질문 2개 모두 수업 시작 전에 막혔다.** 각 질문에서 실제 텍스트 모델은 한 번 실행됐으나 앱이 명확한 자연어 조건을 `needs_input`으로 잘못 분류했다. SQL 실행은 `not_run`, 수업 계획은 null, 새 음성은 0개다. 보충 질문 2개는 NOT_REACHED이며 실행 실패나 모델 오답으로 임의 집계하지 않는다. job의 기술적 succeeded는 “확인 필요” 답변을 저장했다는 뜻이며 학생 수업 성공이 아니다.

| 항목 | N01 | N02 |
|---|---|---|
| 원시 모델 SQL | 원문 의도·정렬·SQLite 결과 모두 일치 | `qty IN (0,5)`로 작성하여 원문의 `qty=0 OR qty>=5`와 불일치 |
| 현재 원본 데이터 결과 | 정답 결과와 일치 | 정답 결과와 우연히 일치: 원본에 5보다 큰 값이 없음 |
| 원시 설명 | 조건·정렬 요약은 있으나 원본 각 행의 조건값과 최종 결과 설명은 미제공 | 설명은 “0 또는 5 이상”이라고 말해 실제 SQL의 IN 조건과 모순 |
| 앱 동작 | needs_input, SQL 검증 전 중단 | needs_input, SQL 검증 전 중단; 원시 SQL의 의미 오류도 검출 단계에 못 감 |
| 실제 판서·설명 음성 | 계획 없음·음성 없음 | 계획 없음·음성 없음 |
| 보충 질문·복귀 | NOT_REACHED | NOT_REACHED |

N02의 의미 차이는 별도 CPU 반례로 확인했다. 원본을 수정하거나 모델에 다시 보내지 않고, 평가용 사본의 한 qty를 6으로 바꿨을 때 원문 조건은 그 행을 포함하지만 모델 SQL은 제외했다. 이 반례는 사후 검산이며 실제 학생 원본 데이터와 구분해 결과에 저장했다.

계획은 첫 질문 2개+보충 2개, 실제 제출은 첫 질문 2개다. **실제 제출 2개 기준 원시 SQL 의도 정답은 1/2**, 현재 표의 결과 행만 비교하면 2/2지만 의미 정확도로 보고하면 안 된다. **앱의 실질 답변·음성 수업 도달은 0/2**, 원시 SQL과 설명의 명확한 내부 모순은 1/2다. 작은 목적 표본이므로 일반 질문 전체의 정확도로 확대하지 않는다.

첫 질문의 설명 요구는 각각 출력 열, 원본 조건 과정, 다중 정렬의 3개로 총 6개다. 앱이 수업을 만들지 못해 실제 교육 전달은 **0/6**이다. 보충의 선택행 이유·NULL/0 비교·정렬·빈 입력 구분·복귀 등 총 12개 요구는 모두 NOT_REACHED로 남긴다. 원시 SQL의 올바름만으로 판서나 설명 요구를 통과 처리하지 않았다.

두 실행 모두 cold였다. 모델 로딩/생성은 N01 약 5.297/5.515초, N02 약 5.219/3.875초다. 첫 유효한 설명 음성, 단계 공백, 중간 질문 응답 시간은 **측정값 없음**이다. 텍스트 생성이나 “확인 필요” 표시까지의 시간을 첫 설명 음성 시간으로 대체하지 않는다.

검사 도구 자체의 첫 수집에는 collector의 user `question_text`를 `content`로 정규화하지 못한 결함이 있었다. 잘못된 제출 0개 기록은 `independent-final02-assessment.json`에 보존하되 INVALID_TOOL_OUTPUT으로 분리했다. v2의 N01 기본 ASC 동치 미판정도 v3에서 일반 정렬 기본값 정규화로 해결했다. 새 검사 도구 fixture 4개가 통과했으며 실제 모델을 재실행하지 않았다.

이후 제품 파서 수정 후 같은 문항을 다시 실행하거나 저장 답변을 재처리하면 **개발용 회귀 결과**다. 이번 두 독립 최초 실패를 성공으로 덮어쓰거나 새 독립 평가 점수에 합산하지 않는다. 별도 CPU 경계 6개는 이 응답률 분모에 포함하지 않는다.
