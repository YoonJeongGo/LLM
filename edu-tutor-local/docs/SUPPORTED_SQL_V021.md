# 0.2.1에서 질문을 수업으로 연결하는 범위

이 문서는 현재 프로그램의 제한 문법을 설명한다. 실제 모델 성공률은 PROGRESS_BRIEFING.md의 새 독립 평가 결과를 별도로 확인한다. 전체 제품은 NOT_READY, 사람 교육·청취 검토는 H_PENDING이다.

## 새로 지원한 질문

확정한 원본 표 하나에서 출력 열, 행 조건, 여러 정렬 기준을 확인한다. 다음처럼 필요한 조건을 구분해 적는 방식이 가장 명확하다. 예시 이름과 값은 설명용이며 프로그램의 고정 정답이 아니다.

    출력 열: item, score; 행 조건: score >= 0 AND score IS NOT NULL; 정렬 기준: score DESC, item ASC.

그룹 집계는 그룹 열을 앞에, 집계식을 뒤에 명시한다. 그룹 조건은 집계 이후에 적용한다.

    출력: zone, SUM(score), COUNT(*); 행 조건: score >= 0; 그룹 기준: zone; 그룹 조건: SUM(score) > 1; 정렬 기준: SUM(score) DESC, zone ASC.

원본 표의 실제 열 이름만 사용한다. 숫자·NULL 비교, AND/OR/NOT와 일부 완전한 한국어 문장을 지원한다. 한국어의 모든 동의어나 긴 서술을 이해하는 문법은 아니다. 원본 표 이름이 일치하는 표 소개 문장과 계산 과정 설명 요청, 명시적인 무정렬 문장은 처리한다. 임의의 서문이나 추가 비교 요청은 아직 확인 요청으로 돌아갈 수 있다. 알 수 없는 조건을 버리고 나머지만 풀지 않는다. 현재 새 자연어 문법의 식별자는 영문·숫자·밑줄이며, 기존 원문 SQL 경로가 허용하는 표현과 자연어 입력 범위는 서로 다르다.

COUNT, SUM, AVG, 숫자 MIN/MAX와 WHERE/GROUP BY/HAVING/ORDER BY의 제한된 조합을 지원한다. 기존 단순 집계와 조건식 SUM(열 IS NOT NULL) 복구 경로도 보존한다. SUM(조건식)을 COUNT(열)로 무조건 바꾸지 않으며 빈 입력의 SUM 결과는 NULL이다.

## 승인에 필요한 근거

1. 학생 원문과 확정한 원본 표에서 의도를 정한다. 모델이 생성한 SQL을 원래 질문으로 바꾸지 않는다.
2. 후보 SQL의 구조를 원래 의도와 비교한다. 열·조건·그룹·정렬 우선순위와 방향을 대조한다. 한 표에서 값이 우연히 같다는 이유만으로 승인하지 않는다.
3. 행별 조건값(TRUE/FALSE/UNKNOWN), 포함 행, 정렬과 집계의 중간값을 별도로 계산한다. 격리한 SQLite 실행 결과와 일치해야 상세 수업을 만든다.
4. 같은 근거와 원본 행·셀 식별자를 대사·판서·선택 행 재설명에 사용한다. 앱이 교정한 답은 원시 모델 답과 별도로 기록한다.

정렬이 없으면 행 순서를 보장하지 않는다. 여러 정렬 기준이 모두 같은 동점 행의 내부 순서도 보장하지 않는다. SQLite의 NULL/BINARY 정렬과 계산을 검증하며 Oracle 등 다른 DBMS의 결과를 검증했다고 주장하지 않는다.

모델 자유 설명의 전체 의미가 자동 검증되는 것은 아니다. 명시한 결과 배열과 제한된 개념 모순을 검사하며, 확인되지 않은 원시 문장을 학생에게 그대로 읽지 않는다. 검증된 계산에서 구성한 대사도 자연스러움과 교육 효과는 사람 검토가 필요하다.

## 남겨 둔 제한

JOIN, CTE, 중첩 질의, 윈도우 함수, SELECT DISTINCT, LIMIT/OFFSET, 출력 산술식, 특수 COLLATE와 모호한 형변환은 이번 상세 수업 범위에 넣지 않았다. 숫자 집계의 TEXT 열과 중복 출력 열도 제외한다. 일부 내부 SQL 검증이 상수 BETWEEN/IN을 처리하더라도 새 자연어 입력에서 그 문법까지 지원한다고 안내하지 않는다.

원본 표·조건이 없거나 비교값이 잘렸으면 확인을 요청한다. needs_input에는 실제 정보 누락뿐 아니라 앱의 제한 문법이 원문 의미를 확정하지 못한 경우도 포함한다. 사람이 이해할 수 있는 질문을 사용자 잘못으로 분류하지 않는다. 사진은 OCR 후보와 실제 원문을 대조해 수정·확정한 뒤 풀이한다. OCR 성공과 사람이 교정한 뒤의 풀이 성공은 다른 지표다. 사진의 누락 조건을 모두 자동 발견한다고 보장하지 않는다.

## 증거의 구분

과거 최종 SQL 60문항의 저장 답변을 새 코드로 처리한 결과는 개발용 회귀다. 첫 독립 평가에서 도입 문장 처리 결함을 발견한 뒤 해당 답변은 개발 회귀로 전환했다. 후속 독립 r2와 최종 r3는 각각 추가 코드 수정 전에 별도로 고정한 지원 20개·경계 8개이며, 제한 문법을 명확히 쓴 질문에 대한 시험이다. r3는 앱19/20계획·응답SQL19/19이며 원시18/20과 앱교정1개를 분리한다. LEAD 자연어 요청의 needs_input 오분류와 부가 비교 설명 미지원은 남아 있다. 일반적인 모든 한국어 질문의 정확도나 사람의 수업 검토 결과로 확대하지 않는다.
