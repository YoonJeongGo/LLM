# v0.2 백엔드 변경과 검증 범위

이 문서는 구현과 CPU 계약 검사를 설명한다. 실제 모델·음성·브라우저의 최종 결과나 교육 실사용 준비 완료를 선언하지 않는다. 실제 회차의 결과는 `runs/phase2/current` 및 최종 인수 보고서에서 별도로 확인한다. 기존 실패·학습·평가 기록은 유지한다.

## 원본 문제와 계산 근거

- `src/edu_tutor/problems/models.py`: 원문, 과제 종류, DBMS, 확정 상태, 표/열/값, 주어진 SQL, 출처와 revision을 보존한다. 표·행·열·셀 ID는 같은 원본에서 안정적으로 생성된다. 새 가정은 별도 namespace이며 원본 값을 바꾸지 않는다.
- `src/edu_tutor/problems/pipeline.py`: 일반 설명과 원본 자료가 필요한 수치 질문을 구분한다. 모호한 입력을 만능으로 이해하는 파서는 아니다. 표가 필요한 계산에 표가 없으면 조건 확인 대상으로 남긴다. 문맥에 있는 선택 셀을 이용해 한 열의 모든 값을 NULL로 보는 제한된 새 가정을 해석하며, 질문의 열과 선택한 열이 충돌하면 확인을 요구한다.
- `src/edu_tutor/problems/evidence.py`: 기존 격리 SQLite 실행기를 재사용한다. 입력 확인, 이름 해석, 실행, 독립 집계 대조, 질문 의도, 기대 결과 대조, 설명 범위, 사람 검토를 각각 기록한다. 실사용에는 독립 정답이 없으므로 `expected_result_check=not_available`을 유지한다.

학생이 준 SQL의 결과 질문은 원문 SQL을 그대로 실행한다. SQL 작성 질문은 모델 후보를 실행하는 것과 별도로 지원 범위 내 집계·대상 열·출력 순서·조건·그룹 구조를 검사한다. `COUNT(*)`가 실행된다는 이유로 “NULL이 아닌 값 수” 요청의 정답으로 처리하지 않는다. 잘못된 후보는 실제 스키마와 오류로 최대 한 번 수정 요청하며, 해결되지 않으면 수치 강의를 중단한다.

지원 범위는 하나의 표에 대한 기본 `COUNT`, `SUM`, `AVG`, `DISTINCT`, 확인된 `WHERE`, 열 기준 `GROUP BY`, `HAVING`이다. 숫자 집계는 포함 값·합계·개수·NULL 제외 셀·그룹 구성과 연결되고, 별도 계산을 SQLite 집계 결과와 대조한다. 구조화된 조건이나 집계 의도를 학생이 제공한 경우 그 사실을 `user_structured_intent`로 표시한다. 모든 자연어의 의미를 독립 증명한 것으로 표시하지 않는다.

유효한 별칭·CTE·JOIN을 단순 문자열 목록으로 “없는 열”이라고 판정하지 않는다. 주어진 SQLite 읽기 SQL이 안전하게 실행되면 그 결과를 제시할 수 있지만, 지원 밖 중간 계산 추적은 `outside_supported_trace`로 남긴다. Oracle/PostgreSQL/MySQL 문제를 SQLite 성공으로 검증하지 않는다. 복잡한 자연어 조건, 모든 SQL 동치성, 모든 DBMS, 임의 DDL/DML은 일반 지원 범위가 아니다.

## 답·판서·음성의 출처

`src/edu_tutor/api/app.py`는 다음을 분리해 저장한다.

- `raw_model_response`: 최초 실제 모델 응답 원문.
- `model_attempts`: 최초·최대 한 번 수정 후보와 각 실제 런타임 메타데이터, 출력 잘림 여부.
- `problem` / `original_problem`: 확인한 원본 문제.
- `evidence`: 실제 검증 근거.
- `content`: 학생에게 보여 주는 최종 앱 결과. SQL 작성 과제는 검증된 SQL도 표시한다.

`verification_mode=model_only`는 도구 수정과 수치 강의를 수행하지 않는 진단 경로다. 도구가 얻은 정답은 모델 자체의 정답률로 기록하지 않는다. RAG는 최대 두 자료의 앞 300자씩을 개념 참고로 사용하며 원본 표를 대체하지 않는다. 정답 파일이나 fixture ID를 추론 입력에 넣지 않는다.

`src/edu_tutor/lessons/verified.py`는 수치 강의를 공유 근거에서 직접 구성한다. 모델에게 판서 숫자를 다시 생성시키지 않는다. COUNT 원본 행/셀 강조, AVG 합계·개수, WHERE 이후 행, 그룹, HAVING 이전 집계, 최종 SELECT 표를 연결한다. 이 순서는 학습용 논리 단계이며 DB의 물리 실행 추적이 아니다. 수치 강의의 새 LLM 계획 호출은 없다.

일반 개념의 모델 자유 설명 전체는 자동으로 검증되지 않는다. `src/edu_tutor/problems/ddl_examples.py`는 실제 모델이 만든 “설명용 새 예시”에서 작은 CREATE TABLE, 리터럴 INSERT VALUES, ALTER ADD COLUMN, DROP TABLE만 AST로 검사하고 안전한 명령으로 재구성해 일회용 메모리 DB에서 실행한다. 원본 문제나 앱 DB에는 쓰지 않는다. 표의 전후 상태와 실행으로 확인한 변화만 판서·대사가 된다. SQL 예시가 없거나 지원 밖이면 임의 예시를 넣지 않고 음성을 차단한다. 모델 자유 설명과 사람 검토는 계속 미검증이다. 초기 강의는 최대 네 단위다.

실제 개념 응답에서 이미 만든 열을 다시 추가하는 오류가 관찰되어, 검증에 실패한 예시는 판서 자체를 만들지 않는다(`plan=null`, 음성 차단). 원문과 실행 전 일부 단계는 감사 기록으로 보존한다. `lessons/concepts.py`는 실제로 차단된 후보에만 원래 질문·응답·실행 오류를 전달해 최대 384토큰으로 한 번 수정한다. 원래 모델·revision·어댑터와 완료 메타데이터가 확인되고 수정 SQL이 전부 실행되어야 판서와 음성을 허용한다. SQL 예시가 없는 응답은 자동 수정하지 않는다.

수정 예약을 원본 응답 ID와 원문 해시로 영구 기록하므로 같은 강의의 재생성, 같은 답의 새 강의, 동시 요청, 취소·실패 후 재시도가 모델 호출을 반복하지 않는다. `lesson.generation.example_model_attempts`에 최초/수정 원문·메타데이터·검사 결과를 구분하고, `raw_repair_response`와 감사 ID를 저장한다. 최초 메시지의 `raw_model_response`와 `content`는 바뀌지 않는다. 이 제한은 잘못된 개념 예시의 한 번 수정이며 기존 SQL 결과·COUNT 생성 경로를 바꾸지 않는다.

`speech.provider.prepare_batch`는 최대 네 짧은 단위를 하나의 순차 TTS 모델 로딩으로 준비하며 완료된 클립부터 API에 저장한다. 캐시 키는 대사·화자·모델 revision·설정과 연결하고 WAV 체크섬도 확인한다. 이 기능의 실제 지연과 발음 품질은 CPU 검사만으로 확인할 수 없다.

두 COUNT의 보충 설명은 실제 긴 음성 생성 관찰 후 원본 열의 표시 이름과 같은 집계값으로 짧게 구성하도록 수정했다. 원시 응답이나 원본 데이터는 바꾸지 않는다. 부동소수점 대사는 기본 6자리 반올림 대신 계산값의 round-trip 문자열을 사용한다. 새 음성의 실제 완료·지연은 루트 실행 보고서에서 별도로 확인한다.

## 문맥·취소·사진

중간 질문은 원강의의 원본 문제, 단계, 선택 셀과 revision을 전달한다. 두 번째 질문의 “모두 NULL” 가정은 원본과 별개로 계산한다. 원강의 객체는 바꾸지 않는다. 대화 generation epoch, 강의 generation epoch, 취소 플래그와 사진 revision이 늦은 답·판서·음성 저장을 막는다. 다른 대화의 모델 작업이 진행 중이면 새 사용자 메시지를 저장하기 전에 409를 반환한다. 입력창 보존과 오디오 위치 복원은 별도 프런트엔드 계약이다.

사진은 실제 OCR 원문, 이후 수정과 확정을 따로 보존한다. `vision/structure.py`는 실제 OCR 문자에 명시된 스키마와 구분된 행만 잠정 구조화한다. 없는 표 이름·열 이름·값을 fixture에서 채워 넣지 않는다. 추출 실패는 그대로 남고, 후보는 정확성 인증이 아니다. 기존 잘린 비교 조건 방어를 유지한다. 사진 revision이 바뀌면 이전 풀이·강의·음성을 무효화하고 새 값을 계산한다.

대화 메시지 조회도 사진 답변의 원본 revision을 현재 저장 사진·확정 상태와 대조한다. 수정·미확정·삭제된 사진의 이전 답변에는 `valid=false`, 사유, 현재 revision을 읽기 전용으로 붙이고 저장된 답변·원문·근거는 바꾸지 않는다. 이러한 답변으로 새 강의를 생성하는 요청은 사진 수정과 같은 잠금 안에서 409로 거절한다. `photo-message-validity-tests.xml`에서 현재/수정/재확정/동일 revision 미확정/삭제, 원본 DB 기록 불변과 기존 사진 회귀 7/7 통과(6.00초). 실제 모델을 추가 실행한 검사는 아니다.

직접 입력 JSON이 사진 출처라고 주장해 저장된 확정 원문을 우회하지 못한다. 사진 풀이 API 또는 실제 `photo_id`로 원본을 불러온다. 이전 버전의 근거 없는 강의는 기록을 유지하되 새 생성·음성을 차단한다. 데모 음성도 오래된 성공 플래그를 믿지 않고 현재 표와 SQLite 결과를 다시 대조한다.

`GET /api/doctor`는 저장된 환경 기록만 읽는다. 일반 로그인·화면 이동에서는 Torch/CUDA 검사를 다시 실행하지 않는다. `cached`, `recorded_at`, `cache_notice`로 과거 GPU·RAM·디스크 값임을 표시한다. 사용자가 직접 요청한 `POST /api/doctor/refresh`만 공통 작업 큐·GPU lease·60초 예약 예산으로 새 진단을 수행한다. 진행 중인 모델 작업이 있으면 409다.

- `runs/phase2/current/backend-final-tests.xml`: 기존 API·doctor·신규 계약 71개 중 69개 통과, 새 캐시의 Path import 누락으로 2개 실패. 누락을 수정했다.
- `runs/phase2/current/backend-guards-final-tests.xml`: 출처·기존 강의·데모·doctor 방어와 계산 계약 19/19 통과.
- `runs/phase2/current/backend-short-final-tests.xml`: 마지막 짧은 대사·NULL 조건·수치 정밀도 보완까지 반영한 백엔드 20/20 통과, 21.71초. 기존 테스트를 삭제하거나 실패 조건을 약화하지 않았다.
- 실제 T01은 개념 질문에 SQL 작성용 응답 형식을 따라 `SELECT ...`를 내는 실패가 관찰됐다. 개념 과제의 프롬프트에서 SQL 답안 JSON 지시를 제거했다. 또한 한글 조사에 붙은 `DDL이`, `INSERT와`를 놓치던 단어 경계를 바로잡았다. 고정 SQL 예시를 넣지 않았다. `concept-repair-tests.xml` 23/23 통과, `concept-prompt-repair.json`에 query_result/write_sql의 전체 메시지 바이트 해시가 변경 전후 같음을 기록했다. 실제 재실행 결과는 별도 보고서 대상이다.
- 그 뒤 실제 모델의 중복 열 예시 실패를 보존하고 판서 차단·1회 수정 제한을 추가했다. `concept-example-repair-tests-final.xml`에서 신규·기존 백엔드와 DDL 검사 49/49 통과, 15.12초. 수정 성공/동일 오류/SQL 없음/잘림/다른 어댑터/취소/동시 요청/다른 강의 재시도 및 원문 불변을 검사했다. 테스트 모델은 명시적 대역이며 실제 수정 성공을 뜻하지 않는다.
- 저장된 실제 T01 응답을 다시 실행했을 때 언어 표기가 없는 코드 블록을 SQL 후보로 찾지 못하는 누락이 드러났다. 시작 명령이 CREATE/INSERT/ALTER/DROP인 언어 미지정 블록도 같은 AST·실행 검사를 받게 수정했다. SQL 명시 블록과 섞여 있어도 원래 순서를 유지하고, 닫히지 않거나 잘못된 SQL 후보는 차단한다. `concept-bare-fence-tests.xml` 56/56 통과, 14.10초. 실제 저장 원문을 CPU로 읽어 `duplicate column name: score`, `plan=null`, 음성 차단을 확인했다. 해당 회차에서는 아직 모델 수정 호출이 없었으며, 이 파서 수정은 모델 재시도를 추가하지 않는다.

검사에는 실행 가능하지만 의미가 틀린 COUNT, 뒤바뀐 집계 출력 순서, 별칭/CTE, WHERE/GROUP/HAVING, NULL 가정 원본 보존, 원시 모델 출력 보존, 수정 요청 한도, 두 번의 추가 질문, 사진 평균 90→60 수정과 이전 강의 무효화, 다른 대화 점유 409, 악성 DDL/함수/ATTACH/PRAGMA 차단이 포함된다. 모델 호출은 명시적 테스트 대역이며 정답률이나 실제 음성 품질 증거로 사용하지 않는다.

모델의 일반 교육 정확성, 자유 설명 전체의 타당성, 발음·청취성, 사용자 이해도는 이 코드 검사로 확인되지 않는다. `human_review=not_reviewed`와 교육 readiness `NOT_READY`를 유지한다.
