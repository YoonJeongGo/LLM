# v0.2 모델 판단

판정: 기본 Qwen3-1.7B를 유지하고, 기존 50-step 어댑터는 후보 상태로 보존한다. 교육 실사용 준비는 NOT_READY다. 검증 도구가 계산값을 고친 것과 모델의 원시 응답 정확도는 별개다. 이번 회차에는 기반모델/GPU 추가 학습, 새 모델 다운로드, 외부 유료 API를 실행하지 않았다.

## 확인된 오류와 해결 범위

- 이전 12문항 중 SQL 11문항의 동일 프로토콜은 기반 3/11, 어댑터 3/11이다. 어댑터의 미요구 별칭을 잘못 감점했던 채점 결함을 별도 교정하면 저장 응답 재채점은 4/11이다. 학습 개선을 뜻하지 않는다. 문항별 증거는 `runs/phase2/current/audit/PREVIOUS_EVALUATION_AUDIT.md`에 있다.
- 실제 T03 두 번째 질문에서 모든 score가 NULL인 가정을 모델은 `3, 1`로 설명했다. 앱의 독립 계산은 `3, 0`이다. `web/test-results-phase2-live/evidence.json`에 양쪽 원문을 보존했다. 출력 포맷을 고치는 것만으로 이 계산 오류를 설명할 수 없다. 작은 표에서도 모델의 신뢰성을 가정할 근거가 부족하다.
- T01은 개념 질문인데 SQL 답안 JSON을 강제하던 앱 지시가 잘못됐다. 개념 지시 분리 후 실제 응답 형식은 개선됐지만, 새 예시에서 이미 있는 score 열을 ALTER ADD로 다시 추가했다. 전자는 확인된 프롬프트 결함, 후자는 실제 모델 예시 오류다. 예시 검증/한 번의 수정으로 방어하되, 원래 답변을 정답으로 바꾸어 기록하지 않는다.
- 이 예시에 실제 SQLite의 `duplicate column name: score` 오류를 전달한 한 번의 수정에서도 모델은 같은 SQL을 반복했다. 최종 `T01-concept-2-example-repair-final.json`은 판서 없음·음성 차단이며 이 질문의 성공으로 세지 않는다. 첫 질문의 CREATE 예시 성공을 바꿔 말한 두 번째 질문 전체 성공으로 확대하지 않는다. 또한 언어 표기 없는 코드 블록을 놓치던 추출기 결함을 수정한 뒤 실행한 결과다.
- 사진 3종의 실제 전사와 수동 편집을 분리했다. 문자 전사가 있더라도 구조화된 표가 자동 추출되지 않았다. 수동 편집 뒤 평균 90→60 계산은 사진 인식 성공률이 아니다.
- 새 기본모델 진단 N12는 `NVL(NULL,'없음')`이 NULL을 반환한다고 잘못 설명했다. [Oracle19c 공식 NVL 문서](https://docs.oracle.com/en/database/oracle/oracle-database/19/sqlrf/NVL.html)는 첫 인수가 NULL이면 두 번째 인수를 반환한다고 정의한다. 이는 문서 대조로 확인한 의미 오류이며 Oracle 엔진을 실행한 결과나 사람 검토는 아니다. N03의 WHERE/평균 조건 혼동, N05의4/3대신3/3, N09의 미일치 LEFT JOIN 행을1건으로 세는 오류도 보존했다. `diagnostics/base-v02-model_only/assistant-observations.json` 참조.
- 기존 음성은 짧은 질문에도 27.6초·64.72초였고 시작 지연이 컸다. 공유 계산에서 대사를 짧게 구성하고 정상 종료 검사를 추가했지만 10초 내 첫 수업 목표는 달성하지 못했다. 모델 파일 캐시와 GPU 모델 상주는 다르다.

앱의 거절을 모두 모델의 능력 부족으로 돌릴 수는 없다. 새 진단 N07은 모델이 올바른 SQL을 JSON 코드블록 안에 작성했지만 당시 추출기가 읽지 못했다. 형식만 해제해도 자연어의 필터·그룹·정렬 요구를 현재 제한된 의미 검사기가 독립 확인하지 못하므로 앱은 중단해야 한다. 따라서 추출 오류의 교정 채점, 검증기 지원 범위, 실제 모델 오답은 별개다. 모델을 바꾸는 것만으로 앱의 답변 coverage가 자동으로 늘지는 않는다. 사용자가 직접 준 SQL의 결과 계산과 자연어에서 SQL을 작성하는 문제도 다른 능력이다.

새 진단의 확정 수치와 실행 범위는 `PHASE2_ACCEPTANCE.md` 및 `runs/phase2/current/diagnostics/`의 최종 보고서를 기준으로 읽는다. 개념 설명 전체, 자연스러운 발음, 이해도는 자동 채점으로 통과 표시하지 않는다.

## 다음 선택지와 비용

| 선택 | 예상 이점 | 비용과 미확인점 |
|---|---|---|
| 현 모델 + 검증 도구 유지 | 추가 모델 저장 없이 COUNT/SUM/AVG 등 지원 범위에서 숫자 전파를 통제 | 자유 설명 오류가 남고, 지원 밖 SQL은 중단한다. 현재 실측 지연은 인수 보고서에 전부 보존한다. |
| 검토된 데이터로 제한 추가 학습 | 반복되는 과제 형식·예시 일관성 오류를 겨냥할 수 있음 | 사람 검토 데이터와 새 독립 평가부터 필요. 이전 50-step으로 개선이 입증되지 않았다. 현재 8GB 환경의 짧은 학습 실행 이력이 운영 학습 적합성을 증명하지 않는다. 새 예산·보존 정책 승인 전 실행하지 않는다. |
| 다른 소형 모델 1종 비교 | 학습 전에 기본 능력 한계를 분리할 수 있음 | 후보는 Qwen3-4B-Instruct-2507. 공식 저장소 표시 약 8.06GB, non-thinking 전용 4.0B 모델이다. 받기 전 exact revision과 실제 파일 크기를 다시 확인해야 한다. |

4B 후보의 사양은 [공식 모델 카드](https://huggingface.co/Qwen/Qwen3-4B-Instruct-2507), 표시 저장량은 [공식 파일 목록](https://huggingface.co/Qwen/Qwen3-4B-Instruct-2507/tree/main)을 2026-10-26 확인했다. 이 제품의 한국어 SQL 성능이나 이 PC의 실행 속도를 입증한 자료는 아니다.

4-bit 실행 시 가중치 산술 하한은 약2GB지만 런타임·양자화 메타데이터·일부 비양자화 텐서·KV 캐시가 추가된다. 짧은 2048토큰 설정에서 총 VRAM 4–7GB를 초기 실험 계획치로 잡되 **실측이 아닌 추정**이며 OOM 가능성이 있다. 원본 가중치를 내려받아 로딩 때 양자화하는 현재 방식에서는 다운로드가 2GB로 줄지 않는다. 단일 원본 보관 약8.1GB에 임시 캐시/중복 여부를 더해야 하고, 중복이 생기면 약16.2GB를 추가 예약해야 한다. 모델 전환 지연과 첫 음성 지연은 측정 전 알 수 없다. 현재 ML 프레임워크를 자동 업그레이드하지 않는다.

우선 결정할 한 가지는 **다섯 실제 장면의 사람 검토 후, 현 모델의 지원 범위를 유지할지 아니면 새 소형 모델 1종을 독립 문제로 비교할지**다. 지금은 다운로드/학습 승인을 요청하거나 실행하지 않는다. 비교를 선택할 때만 정확한 모델 revision·파일 크기·VRAM/시간 상한·새 미사용 평가 묶음을 준비해 그 작업 범위를 승인받는다. 기존 어댑터의 자동 승격은 하지 않는다.

## 독립 평가 조건

현재 공개18문항과 이미 결과를 확인한 새12문항은 후속 개발 자료다. 이 결과를 보고 구현을 고치거나 학습 데이터를 만들면 다음의 독립 성능 증거로 재사용하지 않는다. 다음 비교에는 사람이 검토한 새 문제/정답을 추론 프롬프트와 RAG에서 분리하고, 기본 모델·후보 모델·도구 포함 앱의 결과와 coverage, 잘림, 없는 열, 조건 창작, 실행 실패, 첫 검증 음성 시간을 각각 기록한다. 정답률 상승만으로 교육 READY를 선언하지 않는다.
