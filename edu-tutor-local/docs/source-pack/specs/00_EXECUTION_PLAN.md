# 연속 실행 계획과 게이트

한 번 전달받은 요청을 아래 순서로 진행한다. **게이트는 사람이 매번 승인하는 지점이 아니라,
코드와 실행 증거로 다음 단계의 기반을 확인하는 지점**이다. 안전 승인 범위 밖의 조치는 예외다.

| 단계 | 작업 | 의존 | 완료 게이트 |
|---|---|---|---|
| P0 | 작업 공간 보존, 환경 점검, 기록 체계 | 없음 | doctor JSON·실제 환경·의존성 계획·상태 파일 |
| P1 | 백엔드·프런트엔드 뼈대, 안전한 작업 관리, 로컬 실행 | P0 | 건강 확인·로그·큐·취소·기본 UI 테스트 |
| P2 | 로컬 텍스트 모델 기준선과 채팅 | P1 | 실제 모델 응답 또는 명확한 GPU blocker; CPU 경로 테스트 |
| P3 | 교육 데이터·QLoRA·CPU 검증·GPU 제한 학습 | P0/P2 | gradient·가중치 변경·마스킹·저장·재로딩 증거 |
| P4 | 교육자료 검색·출처·SQL 결과 검증·전후 비교 | P1/P2 | 검색/삭제/출처 매핑·평가 누수 방지·자동 채점 테스트 |
| P5 | 관리자·학습 제어·모델 구조·지표 통합 | P1/P3/P4 | 실제 상태 반영·GPU 경합 차단·모델 선택 테스트 |
| P6 | 강의 계획·판서 엔진·교체 가능한 2D 아바타 | P1/P2 | 스키마 검사·판서·손 위치·일시정지·복원 테스트 |
| P7 | 한국어 로컬 TTS·판서/음성 동기화·중간 질문 | P2/P6 | 실제 음성 파일·재생 시간 기반 진행·이전 작업 폐기 |
| P8 | 사진 읽기·원문 편집·확정 후 강의 | P2/P6 | 실제 인식 또는 차단·확정 게이트·누락 조건 처리 |
| P9 | 전체 통합·접근 제어·품질 확인·패키징 | P0~P8 | 증거 목록·정상/실패 E2E·설치 문서·릴리스 보고 |

## 각 단계에서 할 일

### P0
기존 Git 상태·AGENTS.md·파일을 확인한다. 프로젝트가 없으면 최소 폴더를 만든다.
doctor는 모델 다운로드 없이 실행 가능해야 한다. Python 3.11을 새 환경 기본으로 검토하고,
이미 작동하는 호환 환경은 유지한다. Windows/WSL/Linux와 사용자 PC/원격 컨테이너를 구분한다.
기술 버전은 최신이라는 이유만으로 채택하지 말고 공식 문서·설치·import로 호환성을 확인한다.
네트워크가 없으면 미확인 내용을 표시하고 기존 lockfile을 우선한다.

### P1
API와 UI를 먼저 실제로 연결한다. 모델이 없으면 “모델 미설치/미검증”을 표시한다.
정상 실행 화면에 더미 답변을 자동 표시하지 않는다. 더미는 명시적인 테스트 환경에서만 쓴다.
작업 큐·파일 잠금·상태 전이·취소를 모델에 의존하지 않고 테스트한다.

### P2
기본 공개 모델 하나를 사용해 한국어 대화, 스트리밍, 중단을 구현한다.
모델 가중치가 없는 환경에서도 입력 검증·채팅 저장·오류 UI는 테스트한다.
실제 GPU 실행 불가를 앱 전체 개발 중단의 이유로 쓰지 않되 기준선 검증 pass로 바꾸지 않는다.

### P3
데모 데이터 24/8/12개 이상(train/validation/test)을 새로 작성하되,
수량 채우기를 위해 같은 문제의 이름·숫자만 바꿔 다른 split에 넣지 않는다.
먼저 tiny Qwen3 CPU LoRA 배선 테스트, 그다음 실제 GPU smoke와 제한 데모 학습을 수행한다.
다음 단계로 넘어가는 데 중요한 것은 학습이 실제 작동하는지이며,
50 step으로 교육 성능이 반드시 높아진다는 기준을 만들지 않는다.

### P4~P5
RAG를 학습과 분리한다. 관리자 메뉴에서 모델·어댑터·데이터·검색·학습 상태가 연결되어야 한다.
학습 결과가 나쁘면 기본 모델을 유지하고 새 어댑터를 후보 상태로 둔다. 자동 승격하지 않는다.

### P6~P8
우선 검증 가능한 강의 데이터로 렌더러를 테스트하고, 이어 실제 모델 계획을 연결한다.
정적 예제 재생은 `demo_fixture`로 표시하고 실제 LLM 강의 성공으로 계산하지 않는다.
음성·사진은 다른 GPU 모델과 순차 사용한다. 기본 text→lesson→audio→playback 경로가 완성된 후 사진 경로를 합친다.

### P9
코드·프로젝트 지침·문서·테스트를 다시 대조한다. 구현하지 않은 버튼이나 TODO가 필수 기능에 남으면 실패/미완료다.
단위 테스트, 모델 실행 테스트, 실제 장치 통합 테스트를 별도 묶음으로 보고한다.

## 차단되었을 때

예: GPU 없음 → P2 GPU 검증과 P3 GPU 검증은 blocked.
그렇더라도 P1 UI, P3 tiny CPU, P4 검색, P5 관리자, P6 판서 엔진, P8 확인 화면,
P9 보안·패키징은 진행할 수 있다. 각 관련 기능에 `gpu_unverified` 상태를 남긴다.
CPU에 1.7B 모델을 몰래 올려 GPU 테스트를 대체하지 않는다.

예: TTS 설치 충돌 → 별도 TTS venv/프로세스를 검토한다. 해결되지 않으면 무음·자막 모드의
정상 동작은 구현하되, “음성 강의 완료”로 보고하지 않는다.

## 종료 분류

- `LOCAL_MVP_VERIFIED`: P0~P9 필수 기능의 실제 장치 증거가 모두 존재. 품질 연구 완료를 뜻하지 않음.
- `IMPLEMENTED_RUNTIME_BLOCKED`: 구현·가능한 테스트는 수행했으나 실제 모델·GPU 등 필수 검증 차단.
- `PARTIAL`: 필수 구현이나 테스트가 남음.

스크린샷이 예쁘다는 이유로 완료하지 않는다. 실제 기능과 연결된 증거가 필요하다.
