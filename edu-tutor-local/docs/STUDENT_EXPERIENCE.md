## 2. 실제 질문과 수업 흐름

### A. 개념 질문과 DDL 예시

질문 원문: **“DDL이 뭐였지? 테이블 예시로 설명해 줘.”**

최종 `A-final`은 2026-10-27 04:19:29 UTC에 종료했다. 수정 후 같은 질문을 실제 기반 모델에 새로 제출했고, 검색 자료의 정의 인용 → 실행한 CREATE 예시 → 실행한 ALTER 예시의 세 단계가 모두 실제 `audio_playing`·`audio_ended` 이벤트까지 진행했다.

실제 모델은 DDL을 스키마 정의 명령으로 설명하고, 새 설명용 예시로 다음 SQL을 생성했다. 원시 모델 응답 전체는 case JSON에 그대로 보존했다.

```sql
CREATE TABLE students (id INTEGER PRIMARY KEY, name TEXT DEFAULT 'Unknown', score INTEGER);
ALTER TABLE students ADD COLUMN grade TEXT;
```

실제 단계 대사는 다음과 같다. 첫 단계 인용은 칠판과 음성이 동일하며, 다음 두 단계의 수치는 같은 실행 evidence를 사용한다.

1. “참고 자료에서는 이렇게 설명합니다. DDL은 스키마를 정의·변경하는 명령의 분류입니다.”
2. “설명용 새 예시입니다. CREATE TABLE 실행 뒤 students 표에는 열 3개와 행 0개가 있습니다.”
3. “ALTER TABLE은 이 예시의 열을 3개에서 4개로 늘렸습니다. 행은 0개로 그대로입니다.”

이 표는 학생이 준 원본 데이터가 아니라 **모델이 새로 만든 설명용 예시**로 표시한다. CREATE 전후·ALTER 전후의 열과 행은 실제 SQLite 실행으로 확인했다. 정의는 실제 검색 snapshot에 있던 문장 하나를 출처에 귀속해 인용했다. `retrieved_reference_quotation`으로 기록하며, 원시 모델 문장 검증은 `not_established`, 자료 자체의 사실 정확성과 교육 적절성은 별도 인간 검토 대기다. 원문과 자료의 글자 불일치만으로 모델 의미 오류라고 판정하지 않는다.

특정 DDL 정답을 코드에 넣지 않았다. 일반 인용 경로는 질문·원시 모델·실제 검색 자료에 같은 명시적 기술 용어가 있을 때만, 해당 SQLite 범위에서 첫 두 검색 조각의 각 300자 내 짧은 정의 문장 하나를 선택한다. 숫자·SQL·명령형 문장은 제외하고 chunk/document/version/권리 정보를 보존한다. 기존 exact-match 경로를 우선한다. 이는 모델 자유 설명을 검증했다고 주장하는 경로가 아니다.

초기 실패도 보존했다.

- [A 초기 실패](../runs/student-experience/20261027/cases/A.json): 원시 CREATE의 PRIMARY KEY·NOT NULL·리터럴 DEFAULT는 프로그램 허용 범위가 너무 좁아 차단됐다. 이를 모델 오답으로 돌리지 않는다. 이후 모델 수리문 `ALTER TABLE ADD COLUMN name TEXT NOT NULL;`은 대상 테이블이 없어서 실패했다. 당시 검색 자료에는 DDL 정의가 없었고, 나중 자료로 소급 보충하지 않았다.
- [A-fixed 실패](../runs/student-experience/20261027/cases/A-fixed.json): 유효한 CREATE+ALTER가 코드 블록 없이 출력되어 이전 추출기가 놓쳤다. 미검증 음성과 판서를 차단한 실패를 유지했다. 이후 줄 시작 SQL 접미부 전체를 AST로 검사하는 일반 추출 경로를 보완했다.
- 검색어 목록에 DDL/DML/DCL/TCL과 일반 SQL 명령을 추가한 뒤 기존 DDL 문서가 실제 검색됐다. [검색 재검사](../runs/student-experience/20261027/retrieval-fix-current-query.json)는 검색 수정의 근거다. 초기 A와 최종 A의 RAG 조건이 달라졌으므로 이를 모델 자체 정확도 향상으로 해석하지 않는다.

### B. 새로 작성한 작은 표

개발 검증을 위해 직접 작성한 새 예시다. 실제 사용자 데이터나 비공개 평가 문항이 아니다.

| student | team | score | attended |
|---|---|---:|---:|
| 하린 | 청 | 35 | 1 |
| 도윤 | 청 | 25 | 1 |
| 서아 | 청 | 90 | 0 |
| 지호 | 백 | 40 | 1 |
| 유나 | 백 | NULL | 1 |
| 민재 | 홍 | 70 | 1 |

질문 원문: “개발 검증을 위해 직접 작성한 새 예시입니다. 이 SQL의 원본 표에서 WHERE, GROUP BY, HAVING을 거쳐 최종 결과가 나오는 과정을 설명해 줘.”

```sql
SELECT team, COUNT(*) AS people, SUM(score) AS total
FROM study_results
WHERE attended = 1
GROUP BY team
HAVING SUM(score) >= 50
ORDER BY team;
```

실제 앱은 원본 6행 → WHERE 통과 5행 → 3개 그룹 → HAVING 통과 2개 그룹을 같은 실행 근거와 안정적인 행 ID로 연결했다. 최종 결과는 `청 / 2 / 60`, `홍 / 1 / 70`이다. NULL 값과 제외된 서아 행도 원본·중간 표에 남는다. 질문별 답을 하드코딩하지 않고 허용된 SQL AST와 실제 SQLite 결과에서 표·대사를 함께 구성했다.

실제 모델 원문에는 “WHERE 절은 attended 열에 1을 설정하여 … 필터링”이라는 오해를 유발하는 표현이 있었다. WHERE는 값을 설정하는 동작이 아니므로 이 자유 설명 전체가 정확했다고 판정하지 않는다. 실제 수업의 수치 설명은 앱이 확인한 evidence에서 만들어졌다.

기존 음성이 멈추고 대기 중인 판서 동작이 취소됐으며, 기존 칠판을 유지한 상태에서 해당 행을 강조했다. 보충 대사는 “원본 1행의 4열 값은 1입니다. 4열이 1인 조건을 만족해 집계 입력에 포함됩니다.”였다. 칠판에는 4열이 attended임을 함께 표시하고 행의 값·WHERE 조건·그룹·COUNT 2·SUM 60·HAVING 근거를 연결했다. 음성은 선택 행의 WHERE 포함 이유로 범위를 좁혔다. 학생이 열 번호 표현을 충분히 이해하는지는 인간 교육 검토 대기다.

보충 음성 재생 후 `lesson_resumed`가 기록됐고 원래 수업의 첫 단계 재개와 나머지 세 단계의 실제 재생까지 확인했다. 원시 후속 모델은 일반 SQL 설명을 만들었다. 정확한 선택 행 설명은 앱이 실행 근거로 구성한 결과이며, 모델이 그 행을 독립적으로 이해했다고 증명한 것은 아니다.

초기 [BC 실패](../runs/student-experience/20261027/cases/BC.json)는 보충 계획을 만들었으나 자동 재생 상태 연결 오류로 보충 음성이 시작되지 않았다. 상태 연결을 수정한 [BC-repaired](../runs/student-experience/20261027/cases/BC-repaired.json)는 약 80자의 SQL 포함 대사 생성 중 768 code frame까지 EOS가 나오지 않아 중단됐다. 이 시도의 243.547초는 청구된 작업 시간이며 WAV 길이가 아니다. 실패한 음성을 게시하거나 재생한 것으로 세지 않았다.

이후 실행 근거에서 짧은 한국어 조건 대사를 구성하도록 수정한 47자 대사가 실제 생성·재생됐다. **대사 길이나 영문 혼합이 EOS 실패의 유일 원인이라는 통제 실험은 하지 않았다.** 원래 실패·runtime completion·예산 사용량은 보존했다.

실제 C는 재생 중 음성 중단·대기 판서 취소·복귀를 검증했다. 모델 응답이나 POST job ID가 늦게 도착하는 경쟁 상태 방어는 CPU/UI fixture에서 검증했다. 실제 GPU 생성 중 취소를 추가 실험한 것으로 보고하지 않는다. 취소 대기의 15초 제한과 늦게 생성된 작업의 독립 취소도 프로그램 검사 범위다.

### D. 정상 사진과 중요한 조건이 잘린 사진

기존 v0.2에서 직접 만든 사용 권한 있는 합성 테스트 이미지 두 장을 사용했다. [이미지 출처](../runs/phase2/current/live/T05-image-provenance.json)를 보존했다. 실제 학생 업로드나 사람의 사진 검토로 보고하지 않는다.

정상 사진의 실제 새 OCR에서 vision worker의 로딩 포함 추론 elapsed는 42.328초였다. 서버의 OCR job 생성부터 succeeded 갱신까지는 49.531초로 별도 측정된다. 둘 다 사진 업로드부터 첫 설명까지의 전체 시간은 아니다. 원문은 SQLite `exam_result(name TEXT, score INTEGER)`의 박강열 80, 유성재 NULL, 김현수 100 및 AVG 질문이다. 초기에는 OCR 텍스트에 표가 있었지만 구조화 표가 비어 있었다. 저장된 실제 OCR 텍스트에서 형식 있는 행을 복원하는 일반 파서를 보완한 뒤 미확정 후보 표 3행을 얻었다. 고정 정답 표를 주입하지 않았고 OCR을 다시 호출하지 않았다.

검증 harness가 후보를 명시적으로 확정하고 실제 풀이·음성 경로를 실행했다. 이는 인간이 사진을 대조해 확정했다는 증거가 아니다. 실제 모델 SQL과 도구 결과는 AVG 90이었으나 원시 설명에는 NULL을 “포함한 데이터”로 평균낸다는 모호한 문장이 있었다. 앱 대사·판서는 합계 180, NULL이 아닌 값 2개, 평균 90이라는 동일 실행 근거를 사용했다. [정상 사진 실행](../runs/student-experience/20261027/cases/D-normal-lesson.json)에 raw와 앱 결과를 구분했다.

잘린 사진의 실제 새 OCR에서 vision worker의 로딩 포함 추론 elapsed는 16.641초였고, 서버 OCR job 생성부터 succeeded 갱신까지는 23.761초였다. 원문 끝의 `WHERE score >=` 뒤 값이 없음을 기록했다. [잘린 사진 확인](../runs/student-experience/20261027/cases/D-cut-review.json)에서 풀이 요청은 HTTP 409로 차단됐다. 누락 임계값을 만들지 않았으며 모델 정답이나 수업 음성도 생성하지 않았다. 이는 정상 수업 완료가 아니라 누락 조건 차단의 성공이다.

서버 OCR job 시간은 [정상 사진 live 기록](../runs/student-experience/20261027/live/D-normal.json)의 `created_at=03:23:11.598153Z`와 `updated_at=03:24:01.128945Z`, [잘린 사진 live 기록](../runs/student-experience/20261027/live/D-cut.json)의 `03:29:16.132012Z`와 `03:29:39.893464Z` 차이다. 사진 업로드와 별개로 생성한 OCR job의 대기·실행·완료 반영 범위를 포함한다. 업로드 제출의 단조 시계 값만으로 이 서버 시각과 직접 연결하지 않았다. 정상 사진 OCR과 확정 후 풀이가 다른 실행 단계에 있어 그 사이 검토·수정·확정 대기도 연속 측정하지 않았다. 따라서 worker 시간이나 job 시간에 33.981초를 더해 사진 업로드부터 첫 음성까지의 종단 간 측정이라고 주장하지 않는다.

해당 텍스트 생성 메타데이터의 `model_load_count=1`은 실제 로딩을 포함한다. 상주 warm 모델과의 통제 비교는 NOT_RUN이다. 뒤 실행이 빠르다는 이유로 warm 결과라고 부르지 않는다. 과거 BC artifact의 UI `cached`는 수업 clip 준비 상태를 나타내 provider의 `audio_steps.cache_hit`와 다를 수 있었다. 최종 구현은 `cached=audio.cache_hit===true`로 provider 캐시 여부를 기록하고, 수업 clip이 이미 준비됐는지는 별도 `lesson_audio_already_ready`로 기록한다. 따라서 각 artifact 시점과 provider 메타데이터를 함께 확인한다. 재사용 WAV sidecar의 과거 로딩 시간은 이번 재생의 로딩으로 계산하지 않는다.

초기 실패의 시간도 별도 case에 남겼다. 초기 BC 첫 음성 113.576초·정지 3.600ms 후 보충 시작 없음, BC-repaired 첫 음성 33.220초·정지 4.200ms 후 EOS 실패다. 실패를 제외한 평균이나 개선율은 산출하지 않았다. 최종 A의 세 번째 음성은 ledger의 모델 작업 청구 시간 `charged_seconds`가 124.437초(로딩 등 포함), WAV 길이는 25.6초였다. 이를 순수 생성 시간이나 WAV 길이로 혼동하지 않는다.

A-final과 BC-voicefix의 실제 모델 생성·수업 전환 검증은 마지막 표 가로 스크롤 보정 전 번들에서 수행했다. 마지막 수정 범위는 Classroom의 좌표·표 대상 가시성·현재 gesture 대상 범위·이전 epoch 중단 방어다. 수정 후 최종 번들 `index-C9-hAYF7.js`의 SHA256는 `efdf0ffdf65027fb53272fbaee7e93b8fa2e95e2761d36d96891f27a2a7b8493`이다. 이 번들은 저장된 실제 수업·WAV를 GET-only로 재생해 확인했으며, 같은 모델 질문을 새 GPU로 다시 실행한 증거가 아니다. 최종 확인 전후 누적 시간 4176.331초·음성 19시도·비전 6회가 같았다. 기존 교육 평가 수치는 변경하지 않는다.

안정 프레임 후속 촬영에서도 앱 번들은 같았고 모델 요청·POST 없이 예산이 유지됐다. 최종 코드 소스 해시는 `02a419105733dfd9092704e8df319f2954723d245ebec4cd705256cb9bd7d662`다. UI의 좌표·가림·폭 검사와 사람이 판단할 교육 가독성을 구분한다.

## 5. 기존 기록 보존과 실행 제한

[최종 보존 감사](../runs/student-experience/20261027/preservation-final.json)는 읽기 전용 DB와 파일 해시를 비교했다. 기존 **376개 DB 행의 ID·내용**, **289개 기존 불변 증거 파일**, **6개 신경망 소스 파일**, 기존 예산의 **104개 request prefix**가 그대로였다. 새 실행의 세션·메시지·작업·사진·수업 행 추가는 기존 행 수정과 구분했다. 신경망 기능을 확장하거나 그 증거를 새 결과로 덮어쓰지 않았다.

예산 파일은 원래부터 누적 기록이므로 전체 파일 해시 불변을 요구하지 않고 이전 request prefix가 엄격히 같은지 검사했다. [추가 승인 기록](../runs/student-experience/20261027/additional-authorization.json)에 따라 음성 한도 12→19, 비전 한도 4→6으로 조정했다. 이는 당시 누적 음성 11회·비전 4회에 **새 음성 8시도·새 비전 2회**를 허용한 것이며 누적 시간을 초기화한 것이 아니다.

최종 모델 실행 종료 시 누적 예산은 **4176.331 / 5400초**(69.606분), 남은 시간은 1223.669초다. 누적 request는 125개, 음성 시도 19/19·비전 6/6이다. 이번 추가 음성 8시도는 성공 7·EOS 실패 1이며, 비전 2회를 모두 사용했다. 실패 시도도 예산에 포함한다. 추가 추론을 요청하거나 자동 재시도하지 않는다.

**현재 사용 제한:** 음성 19/19·사진 6/6 한도가 소진돼 새로운 대사의 음성 생성과 새 OCR은 현재 정책에서 차단된다. 저장된 수업과 이미 생성된 유효 WAV는 재생할 수 있다. 누적 시간 일부가 남았어도 별도 음성·사진 한도를 우회하지 않는다. 검증 예산 소진을 교육 기능 완성으로 해석하지 않는다.

인증, localhost 제한, 직렬 작업 큐, 개별 요청 제한 300초, 누적 90분, 저장 공간 제한을 유지했다. [최종 전체 저장량 검사](../runs/student-experience/20261027/storage-final.json)는 20.676455846GB로 50GB 한도 아래이며 C 드라이브 여유는 약 88GB였다. 삭제나 예산 초기화로 이 조건을 맞추지 않았다.

이번 작업에서 새 학습·새 모델 다운로드·유료 호출·외부 업로드를 시작하지 않았다. 감사한 로컬 작업 기록에도 새 학습·다운로드 작업이 없다. 모델 디렉터리의 변경 중 runtime-structure 메타데이터 갱신은 실제 로딩 관측으로 구분했다. 이 확인은 해당 앱의 로컬/offline 경로와 기록 범위이며 OS 전체 네트워크나 외부 청구 계정 감사는 아니다.

## 6. 남은 오류와 다음 판단에 필요한 근거

- **지연**: 첫 유효 설명과 단계 사이 대기가 학생 수업 목표에 맞지 않는다. 음성 생성 실패도 실제로 한 번 발생했다. 빠른 안내음이나 미리 녹음한 수업으로 이를 성공으로 바꾸지 않았다.
- **모델 설명 능력**: 잘못된 ALTER 수리문, WHERE를 값 설정처럼 표현한 문장, AVG/NULL의 모호한 설명을 원문 그대로 보존했다. SQL 실행이 맞아도 자유 설명 전체가 맞다는 뜻은 아니다.
- **근거 범위**: 자료 인용은 해당 snapshot에 문장이 있다는 근거이며 모든 사실의 외부 검증이 아니다. 앱의 SQLite 실행 근거와 원시 모델 고유 능력을 구분해야 한다.
- **화면 범위**: 좁은 화면에서 대상 셀이 보이지 않던 실패는 수정 후 12개 화면 조건에서 가시성까지 확인했다. 이번 표본 밖의 모든 화면·모든 판서 대상이 검증됐다는 주장은 하지 않는다.
- **사람 검토**: 실제 WAV·전후 스크린샷·단계 대사가 준비돼 있지만 사람이 듣고 읽어 판단하지 않았다. 특히 출처 정의와 예시의 연결, 4열이라는 표현, 한국어 발음과 긴 공백 뒤 이해 유지가 검토 대상이다.

현재 결론은 **제한된 실제 수업 경로와 프로그램 오류 수정은 증거가 있으나, 짧은 준비·전반적 교육 품질 기준은 NOT_READY**다. 새로운 수치 정확도나 실제 학생 사용 적합성을 주장하지 않는다.
