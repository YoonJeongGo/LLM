3. 구현 순서: 먼저 일반적인 단일 표 풀이 경로
범위를 먼저 명시하고, 다음을 기존 근거 모델과 판서 구조에 연결한다.
A. 단일 표 SELECT의 출력 열 선택, WHERE의 명확한 비교·NULL 조건,
   ORDER BY의 여러 정렬 기준과 ASC/DESC·동점 우선순위.
B. 기존 집계에 WHERE와 명확한 GROUP BY/HAVING/ORDER BY가 결합된 유형.
C. 이미 있는 개념·DDL/DML 수업, 선택 행 재설명, 원래 수업 복귀의 회귀 확인.
한 번에 모든 SQL 방언·JOIN·CTE·윈도우함수까지 구현하려 하지 않는다.
이번에 미지원으로 남기는 유형을 정확히 표시하고 전체 목표 완료로 축소 포장하지 않는다.

질문 의도, 후보 SQL, 실행 결과, 중간 표, 대사·판서는 구별한다.
- 의도는 학생 원문/확정한 표에서 추출한다. 모델 SQL에서 정답 의도를 거꾸로 만들지 않는다.
- 현재 자연어 어댑터를 일반화된 제한 문법/구조화 의도로 확장한다.
- 의미가 분명한 지원 범위는 바로 처리하고, 모호한 부분만 구체적으로 확인한다.
- SQL AST로 표/열/조건/정렬/집계를 확인한다. SQL 문자열 완전일치만 요구하지 않는다.
- 후보 SQL을 학생이 직접 제공한 SQL로 바꿔 의도 검증을 우회하지 않는다.
- 실행된다는 사실이나 한 표에서 값이 맞았다는 사실만으로 질문과 동치라고 승인하지 않는다.
- NULL/0/음수/중복/빈 입력/동점과 서로 다른 정렬 방향을 포함한다.
- ORDER BY가 없으면 결과 순서를 보장한다고 가르치지 않는다.
- 행 단위 근거와 열/셀 식별자를 유지해 선택한 행이 왜 남았는지 설명할 수 있게 한다.
- 지원 범위의 중간 결과를 별도 계산하고 격리된 SQLite 결과와 대조한다.
- 결과 숫자/행은 실행 근거에서 대사·판서로 전달한다. 모델이 말한 결과 배열을 맹신하지 않는다.
- 사용 DBMS는 SQLite로 표시한다. Oracle 전용 개념을 SQLite 실행으로 증명했다고 하지 않는다.
- 실제 사용자의 DB가 아니라 격리된 개발 fixture에서만 계산한다.
