[3. 첫 수정: 음성 취소가 텍스트 모델을 닫는 결합 해소]
보고서 J04에서는 취소된 대기 음성의 preflight가 idle 텍스트 worker를 닫아 보충 질문이 cold로 처리됐다.
현재 코드에서 정확한 호출 순서와 소유권을 재현하고, 관련 분기만 최소 수정한다.

요구 동작:
- 취소 요청은 해당 job/request/instance/epoch 소유 작업만 취소한다.
- CPU Heami 대기 작업 취소나 이미 취소된 preflight가 무관한 텍스트 worker를 내리지 않는다.
- 새 작업의 자원 전환 전에 취소·기한·소유권을 다시 확인한다. 오래된 callback이 새 요청을 종료하지 않게 한다.
- 실제로 생성 중인 텍스트를 취소할 때는 정확히 그 요청을 중지한다. 안전한 재사용이 불가능하면 이유를 기록하고 해당 worker만 종료한다.
- GPU가 필요한 사진/학습 등 실제 전환과 CPU 음성 준비를 구분한다. GPU 메모리가 필요하면 기존 직렬 큐와 안전한 해제를 따른다.
- 현재 수업을 듣거나 보충 질문을 하는 정상 활동이 불필요한 idle 종료로 이어지는지 확인한다. 제한된 수업 활동 기반 유지 정책을 검토하되 무제한 heartbeat나 영구 상주로 바꾸지 않는다.
- 기존 최대 세션 수명·종료 규칙을 유지한다. 실제 만료·메모리 압박·다른 GPU 작업으로 내려간 경우는 cold로 정직하게 측정한다.

먼저 모의 경합으로 취소/신규 요청 교차를 확인하고, 실제 학생 경로에서 같은 PID·모델 인스턴스·load count가 유지되는지 검증한다.
성능을 보여주려고 시험에서만 강제로 상주시킨 경로를 일반 학생 기능인 것처럼 보고하지 않는다.

[5. 세 번째 수정: 학생이 요청한 설명을 빠뜨리지 않기]

- 현재 정렬의 우선순위와 동점 처리
- 질문에서 추가로 요구한 NULL/0/빈 입력 등의 구분

현재 원본에 비교할 행이 있으면 그 행을 찾아 표시하고 양쪽을 대조한다.
여러 행 중 의미상 선택이 모호하면 필요한 부분만 확인한다. 원본에 없으면 없다고 밝히고 예시는 별도로 구분한다.
SQL 계산용 조건과 설명 요청을 분리한다. “NULL행과 비교”를 원래 WHERE 조건 변경으로 해석하지 않는다.
검증된 근거에서 대사·강조 셀·판서를 함께 만들며, 핵심 설명 누락 여부를 별도로 검사한다.
한 개의 성공 질문을 특수 분기하지 말고 표현·열 이름·선택행이 다른 변형을 함께 검증한다.
학생에게 내부 입력 형식에 맞춰 다시 쓰라는 요구만 반복하지 않는다.

[7. 실제 검증 — 한 번의 측정으로 전체 합격 처리 금지]
기존 자료로 실패를 재현하고 CPU·웹 영향 검사를 마친 뒤 수정된 서버/빌드를 적용한다.
학생 자료와 진행 중 작업을 보존하며 해당 앱만 안전하게 재시작하고 실제 실행 버전과 설정을 확인한다.
검사 도구의 소유권·입력 선택자·오디오 수집은 무모델 검사로 먼저 확인한다.
실제 모델 호출로 검사 도구 자체의 단순 오류를 반복 디버깅하지 않는다.

검증 묶음:
A. 취소와 warm 유지
  실제 수업→대기 Heami 취소→현재 표의 보충 질문에서 텍스트 worker가 유지되는지 확인한다.
  장부, 취소 응답, 동일 인스턴스/새 인스턴스와 이유를 모두 기록한다.
B. 첫 설명과 보충 설명 지연
  사전에 정한 같은 입력/설정으로 cold와 실제 같은 모델의 warm을 구분한다.
  기존 WAV 캐시와 새 합성을 나누고 UI 제출/질문 버튼부터 의미 있는 설명의 실제 playing까지 잰다.
  첫 유효 텍스트 출력과 첫 유효 음성은 별도다. 안내음과 녹음 재생으로 새 생성 시간을 대체하지 않는다.
  준비·load·generate·이벤트/DB·검증·음성·브라우저 시간을 표시하되 중첩이나 다른 시계를 합산하지 않는다.
  소표본은 전건·실패·최대값을 보여주고 개선율은 같은 조건에서만 비교한다.
C. 설명 충족
  개발 회귀와 구분한 새 질문에서 포함 이유+NULL 비교+정렬 등 요청 항목별 대사/판서 근거를 확인한다.
  답변 가능한 단일 표 범위를 유지하며 지원 밖 문제, 누락 입력, 모호한 후보의 분류도 검사한다.
  평가 답·예상 plan을 제품 입력/RAG에 넣지 않는다. 평가를 보고 수정하면 그 결과는 개발 회귀로 재분류한다.
D. 최종 같은 빌드
  개념, 조건·정렬, 그룹·HAVING, 중간 질문·복귀, 정상/교정/잘린 사진, 취소 후 새 수업을 대표 경로로 확인한다.
  기존 J01~J08 재실행은 회귀이지 새 독립 정답률이 아니다. 사진은 출처·교정 여부·확인 시간을 분리한다.
  완료→설정→강의실 복귀, 반복 중단, 재시작과 저장 수업 재생도 포함한다.
  전부 새 생성할 필요는 없으며 검증 목적에 맞게 저장 자료를 쓰되 새 수업 성능과 구분한다.

품질을 유지하며 기존 목표 warm 첫 설명10초/보충10초/단계 공백2초/정지0.5초를 측정한다.
10초는 달성 보장이 아니다. 실패하면 확인한 병목과 남은 지연을 적고 통과로 바꾸지 않는다.
원인 변경 없는 반복 재시도로 예산을 소진하지 않는다. 한 항목이 막혀도 독립적인 나머지 수정·검증은 진행한다.

[8. 완료 판정과 보고]
16개 기준을 유지한다. 현재9/16을 개발 진척률로 바꾸지 않고, 새 실제 근거로 달라진 기준만 재판정한다.
H_PENDING은 사람이 실제로 듣고 판단해야 한다. 자동검사·AI 텍스트 검토·갤러리 생성으로 H_PASS를 만들지 않는다.
기존 검토 UI로 대표5수업의 정확성·친절함·발음·판서 가독성·질문 충족을 검토할 수 있게 연결한다.
사람 검토를 기다린다는 이유로 다른 완료 가능한 구현을 멈추지 않는다. NOT_READY의 미해결 사유는 기능별로 분명히 남긴다.

최종 응답은 다음 순서다.
1) 학생이 전에는 못했는데 이번에 가능해진 일
2) 실제 수정한 결함과 코드 위치
3) 새 질문의 요청 항목 충족, 실제 대사·표·음성과 오류
4) cold/warm/캐시·새 합성별 전건 시간, 인스턴스와 취소 결과
5) 같은 최종 버전의 회귀·실제 수업·사람 검토를 구분한 판정
6) 잔여 예산과 사용자가 바로 확인할 실행/갤러리 경로
7) ChatGPT 전달용 — 그대로 복사

STATUS.json, HANDOFF.md, docs/PROGRESS_BRIEFING.md, docs/CHATGPT_HANDOFF.md를 서로 맞춘다.
복사 인계는 기준 시각·버전·현재 모델/음성·이번 실제 변화·최신 측정·미검증·막힌 항목·남은 예산·다음 작업을 담는다.
원본 로그를 복제한 거대한 보고서를 반복하기보다 새 변화와 결정에 집중한다.
세션 제한으로 중단되면 안전한 작업 상태와 이어서 실행할 정확한 명령을 남긴다. 완료나 후속 실행을 약속하지 않는다.
