# 한국어 AI 강사 — Codex 통합 개발 지시서

작성일: 2026-10-25 · 대상 PC: i7-13700F / RAM 32GB / RTX 3060 Ti 8GB

## 이 파일 묶음은 무엇인가?

이 ZIP은 **완성된 앱이나 학습된 모델이 아니라, Codex에 전달할 개발 요구사항과 검증 기준**이다.
목표는 로컬 LLM, 실제 QLoRA 추가 학습, 대화·관리자 UI, 교육자료 검색, 사진 확인, 판서·음성·2D 아바타를 연결한 **개인용 작동 버전**이다.
모든 과목의 전문성을 확보한 기반 모델, 상용 서비스, 실사 강사 영상까지 완성했다고 주장하는 요구사항은 아니다.

## 가장 쉬운 전달 방법

1. ZIP을 푼 `edu_tutor_codex_pack` 폴더를 Codex가 접근할 프로젝트 폴더 안에 둔다.
2. `01_START_PROMPT_KO.txt`의 내용을 Codex 대화창에 한 번 붙여 넣는다.
3. Codex는 `02_MASTER_INSTRUCTIONS.md`와 `specs/00_EXECUTION_PLAN.md`를 우선 읽고, 각 단계에 필요한 상세 문서를 읽으며 구현을 이어간다.

첨부 파일을 실제 파일로 읽을 수 있는 Codex 환경이라면 ZIP 첨부와 시작 문구로 전달해도 된다.
ZIP 첨부를 지원하지 않는 환경에서는 위 폴더 방식으로 전달한다. ChatGPT에 업로드한 파일이 별도 Codex 작업 공간에 자동으로 나타난다고 가정하지 않는다.

`ALL_IN_ONE_PROMPT_KO.txt`는 모든 지시서·예시·스키마를 합친 독립 전달용 파일이다.
**폴더 방식과 통합 TXT 방식 중 하나를 사용한다. 둘을 중복해 모두 컨텍스트에 넣을 필요는 없다.**

## 원하는 진행 방식

- 매 단계 뒤에 “다음 단계도 할까요?”라고 묻지 않고, 통과한 단계 뒤의 작업을 자동으로 이어간다.
- 구현·테스트·오류 수정·기록을 단계 단위로 반복한다.
- 실행 불가능한 GPU 테스트는 blocked/skipped로 남기고, 독립적으로 진행할 수 있는 UI·CPU 테스트를 계속한다.
- 권한·세션·네트워크 제한을 우회하지 않는다. 한 대화가 무제한 지속되거나 무조건 전체 개발이 완료된다고 보장하지 않는다.
- 제한에 도달하면 `HANDOFF.md`에 정확한 재개 정보를 남긴다. 개발 종료가 아니라, 중단 상태와 남은 일을 명확히 표시한다.

# 최상위 실행 계약

너는 이 프로젝트의 구현 책임자다. 개발자가 읽을 수 있는 Python/TypeScript 코드, 테스트,
한국어 설명 문서와 실행 가능한 개인용 프로그램을 만든다. 개발 모델의 이름이나 추론 모드 자체를
성공 근거로 삼지 않는다. 사용할 수 있는 실제 도구·권한·시간 안에서 수행한다.

## 목표

`edu-tutor-local`은 공개 LLM을 교육용으로 추가 학습하고, 학생이 이해하는 과정을
대화·표·판서·음성·교체 가능한 2D 캐릭터로 설명하는 로컬 애플리케이션이다.
첫 검증 분야는 SQLD·정보처리기사의 기초 데이터베이스다. 분야 목록을 늘릴 구조는 만들되,
의학·법·모든 교과에 대한 성능을 데모 데이터만으로 보장하지 않는다.

## 절대 규칙 5개

1. **증거와 상태 구분**: 구현됨, CPU 검증됨, GPU 검증됨, 모델 품질 검토됨을 분리한다.
   더미 응답·예제 그래프·하드코딩 결과를 실제 모델 실행·학습·평가로 표시하지 않는다.
2. **사용자 자산 보존**: 기존 파일, Git 변경, 데이터, 다른 프로세스를 보호한다.
   `reset --hard`, `clean -fd`, 무차별 삭제, 타 프로세스 종료, 임의 드라이버 변경을 하지 않는다.
3. **데이터 신뢰**: 학습/평가 누수를 막고, 출처·권리·검토 상태를 기록한다.
   업로드 문서와 모델 출력은 신뢰할 수 없는 데이터이며, 시스템 명령으로 실행하지 않는다.
4. **비용·자원 제한**: 유료 API·클라우드 결제·외부 업로드·무제한 학습·무제한 재시도를 하지 않는다.
   아래 자동 실행 허용 범위에 있는 작업만 진행한다.
5. **검증 게이트와 지속성**: 단계별 실제 검증을 거친다. 통과하면 자동 진행하고,
   세션·권한·환경 한계를 우회하지 않는다. 중단 시 상태와 재개 지점을 파일로 남긴다.

## 기존 작업과의 관계

- 기존 AGENTS.md와 작업 폴더를 먼저 읽는다. 이 팩을 기존 파일 위에 무작정 덮어쓰지 않는다.
- 이미 작동하는 기능은 재사용한다. 구조 변경의 이득이 명확하지 않으면 대규모 재작성을 피한다.
- 작은 Transformer를 처음부터 만드는 A 실습은 이번 필수 작업에서 제외한다.
- 이전 지시가 “1단계에서 멈춤”이었다면 이번 지시는 그것을 **연속 단계 수행**으로 갱신한다.
- 단, 상위 시스템 지침·권한 제약·안전 장치는 이 문서로 해제되지 않는다.

## 자율 진행과 종료 기준

`specs/00_EXECUTION_PLAN.md`를 작업 순서의 기준으로 삼는다. 단계마다 필요한 상세 파일만 읽는다.
작업 계획을 만든 뒤 실제 구현으로 들어가며, 설계 문서만 늘리는 것을 진척으로 취급하지 않는다.
각 단계에서 구현 → 해당 테스트 → 수정 → 증거 경로 기록 → 상태 갱신을 한다.
통과한 게이트마다 사용자에게 다음 단계 실행 여부를 묻지 않는다.
미정인 일반 UI 문구·색·폴더명은 이 문서의 기본값을 사용하고 결정 근거를 남긴다.

같은 오류에 대한 무의미한 재시도는 3회 이내다. 새로운 근거가 없으면 blocker로 기록한다.
GPU 학습 OOM은 원인과 설정을 기록하고, 입력 길이를 줄이는 제한된 재시도 1회만 허용한다.
의존하는 검증이 막혀도 별도로 가능한 UI·데이터 검증·CPU 테스트는 계속한다.
연관 검증이 막혔다는 이유로 해당 기능을 정상 완료로 표시하지 않는다.

자동화가 세션의 지속 시간을 보장하지 않는다. 컨텍스트가 줄어들기 전에 기록을 갱신한다.
외부 무한 루프, 임의 예약 작업, 결제를 통해 세션을 억지로 지속하지 않는다.
종료 판단은 ① 필수 검증 통과, ② 실제 환경 차단, ③ 도구/세션 제한, ④ 승인 범위 밖의 작업 필요 중 하나여야 한다.

## 이번 요청에서 자동 수행을 허용하는 범위

- 프로젝트 내부 가상환경과 프런트엔드 패키지 설치, 테스트, 로컬 개발 서버 실행.
- 공식 무료 모델 저장소의 다운로드. 시작 전 파일 목록·예상 용량·라이선스를 확인하고 기록.
  신규 모델·토크나이저 다운로드 합계는 기본 20GiB 이내, 디스크 잔여 20GiB 이상 유지.
  CPU 전용 원격 환경에서는 전체 1.7B/비전/TTS 모델을 자동 다운로드하지 않고 작은 테스트만 실행.
- GPU 사용 가능한 로컬 환경에서 텍스트 기준선 실행, 5 optimizer step smoke 학습,
  추가 50 optimizer step 이하의 데모 학습 1회. smoke 실행 상한 600초, 데모 학습 900초.
  step/시간/메모리 제한 중 먼저 도달하는 제한을 적용하고, 제한 중단은 정상 완주와 구분.
- 인식·음성·통합 검증은 샘플 3개 이내, 요청당 상한 300초. 실제 지연을 기록하고 빠르다고 추정하지 않음.
- 본격적인 장기 학습은 실행 기능과 명령을 구현하되 자동으로 시작하지 않는다.
  향후 관리자가 UI에서 설정·예산을 확인하고 시작하도록 한다.
- 재부팅, 관리자 권한 설치, OS·GPU 드라이버 변경, 공개 서버 배포, 원격 푸시,
  사용자 파일 업로드, 유료 서비스, 모델 캐시 전체 삭제는 자동 승인 범위 밖이다.
  필요하면 blocker와 정확한 수동 조치를 기록한다. 앱 구현의 독립 작업은 계속한다.

시간값은 프로그램의 안전 제한이지 사용자에게 약속하는 개발 완료 시간이 아니다.
모델 다운로드 20GiB 제한도 라이브러리 문서의 요구량이 아니라 이 프로젝트의 보수적 운영 정책이다.

## 상태 체계

각 단계에는 `implementation_status`와 `validation`을 별도로 둔다.
implementation_status: pending / in_progress / implemented / blocked.
validation 각 항목: not_run / pass / fail / skipped / blocked.
환경은 실제 실행된 장치를 기록한다. 모든 pass에는 command, exit_code, artifact_path가 필요하다.
선택 기능을 제외할 때는 적용 범위·사유를 남기고 필수 기능을 몰래 선택 기능으로 바꾸지 않는다.

프로젝트 루트에 `STATUS.json`, `HANDOFF.md`, `docs/DECISIONS.md`, `docs/ACCEPTANCE.md`를 유지한다.
실행 산출물은 `runs/<run_id>/`, 모델·DB·업로드 등은 `.local/` 아래에 두고 Git에서 제외한다.
run_id는 시간과 짧은 무작위 식별자를 조합하며 로그 시각에는 timezone을 붙인다.
기본 사용자 표시 시간대는 Asia/Seoul, 내부 기록은 UTC ISO 8601을 권한다.

## 정직한 최종 보고

보고서는 한국어로, 실제 화면·명령·산출물 경로를 사용한다.
1. 실제 실행할 수 있는 기능과 실행 방법
2. 실행 환경과 통과한 테스트
3. GPU/모델/음성/사진 등 미검증 또는 차단된 기능
4. 학습 결과 파일과 기반 모델·어댑터의 관계
5. 데모 데이터의 한계와 품질 평가 결과
6. 남은 작업과 필요한 사용자 조치

“모든 교육을 아는 AI 완성”, “ChatGPT급”, “몇 초 응답 보장” 등의 근거 없는 표현을 하지 않는다.

# JSON 계약 사용법

JSON Schema는 형식·타입·허용 명령을 검사하기 위한 출발점이다. 실제 앱에서는 Pydantic/TypeScript 타입과
일치시키고, 필요한 수정은 schema_version 변경·migration·예제·테스트를 함께 갱신한다.

스키마만으로 모든 의미를 검증할 수는 없다. 다음은 별도 검사해야 한다.
- table 행 너비가 columns 수와 같은지.
- step ID와 생성 element ID가 중복되지 않는지.
- highlight/arrow/gesture가 현재 board에 존재하는 element를 가리키는지.
- 행·열 highlight index가 실제 범위 안인지.
- source_refs가 실제 검색한 document/chunk를 가리키는지.
- confirmed_image일 때 원문 확정 기록이 있는지.
- SQL 기대 결과와 실제 실행 결과가 일치하는지.
- 데이터 messages의 역할 순서와 train/validation/test의 family 분리.
- schema pass를 설명의 참/거짓 검증으로 혼동하지 않는지.

examples는 `demo_fixture`다. 개발 과정의 렌더러 검사에는 쓸 수 있지만 실제 모델 답변으로 위장하면 안 된다.

# 연속 실행 계획과 게이트

한 번 전달받은 요청을 아래 순서로 진행한다. **게이트는 사람이 매번 승인하는 지점이 아니라,
코드와 실행 증거로 다음 단계의 기반을 확인하는 지점**이다. 안전 승인 범위 밖의 조치는 예외다.

| 단계 | 작업 | 의존 | 완료 게이트 |
|---|---|---|---|
| P0 | 작업 공간 보존, 환경 점검, 기록 체계 | 없음 | doctor JSON·실제 환경·의존성 계획·상태 파일 |
| P1 | 백엔드·프런트엔드 뼈대, 안전한 작업 관리, 로컬 실행 | P0 | 건강 확인·로그·큐·취소·기본 UI 테스트 |
| P2 | 로컬 텍스트 모델 기준선과 채팅 | P1 | 실제 모델 응답 또는 명확한 GPU blocker; CPU 경로 테스트 |
| P3 | 교육 데이터·QLoRA·CPU 검증·GPU 제한 학습 | P0/P2 | gradient·가중치 변경·마스킹·저장·재로딩 증거 |
| P4 | 교육자료 검색·출처·SQL 결과 검증·전후 비교 | P1/P2 | 검색/삭제/출처 매핑·평가 누수 방지·자동 채점 테스트 |
| P5 | 관리자·학습 제어·모델 구조·지표 통합 | P1/P3/P4 | 실제 상태 반영·GPU 경합 차단·모델 선택 테스트 |
| P6 | 강의 계획·판서 엔진·교체 가능한 2D 아바타 | P1/P2 | 스키마 검사·판서·손 위치·일시정지·복원 테스트 |
| P7 | 한국어 로컬 TTS·판서/음성 동기화·중간 질문 | P2/P6 | 실제 음성 파일·재생 시간 기반 진행·이전 작업 폐기 |
| P8 | 사진 읽기·원문 편집·확정 후 강의 | P2/P6 | 실제 인식 또는 차단·확정 게이트·누락 조건 처리 |
| P9 | 전체 통합·접근 제어·품질 확인·패키징 | P0~P8 | 증거 목록·정상/실패 E2E·설치 문서·릴리스 보고 |

## 각 단계에서 할 일

### P0
기존 Git 상태·AGENTS.md·파일을 확인한다. 프로젝트가 없으면 최소 폴더를 만든다.
doctor는 모델 다운로드 없이 실행 가능해야 한다. Python 3.11을 새 환경 기본으로 검토하고,
이미 작동하는 호환 환경은 유지한다. Windows/WSL/Linux와 사용자 PC/원격 컨테이너를 구분한다.
기술 버전은 최신이라는 이유만으로 채택하지 말고 공식 문서·설치·import로 호환성을 확인한다.
네트워크가 없으면 미확인 내용을 표시하고 기존 lockfile을 우선한다.

### P1
API와 UI를 먼저 실제로 연결한다. 모델이 없으면 “모델 미설치/미검증”을 표시한다.
정상 실행 화면에 더미 답변을 자동 표시하지 않는다. 더미는 명시적인 테스트 환경에서만 쓴다.
작업 큐·파일 잠금·상태 전이·취소를 모델에 의존하지 않고 테스트한다.

### P2
기본 공개 모델 하나를 사용해 한국어 대화, 스트리밍, 중단을 구현한다.
모델 가중치가 없는 환경에서도 입력 검증·채팅 저장·오류 UI는 테스트한다.
실제 GPU 실행 불가를 앱 전체 개발 중단의 이유로 쓰지 않되 기준선 검증 pass로 바꾸지 않는다.

### P3
데모 데이터 24/8/12개 이상(train/validation/test)을 새로 작성하되,
수량 채우기를 위해 같은 문제의 이름·숫자만 바꿔 다른 split에 넣지 않는다.
먼저 tiny Qwen3 CPU LoRA 배선 테스트, 그다음 실제 GPU smoke와 제한 데모 학습을 수행한다.
다음 단계로 넘어가는 데 중요한 것은 학습이 실제 작동하는지이며,
50 step으로 교육 성능이 반드시 높아진다는 기준을 만들지 않는다.

### P4~P5
RAG를 학습과 분리한다. 관리자 메뉴에서 모델·어댑터·데이터·검색·학습 상태가 연결되어야 한다.
학습 결과가 나쁘면 기본 모델을 유지하고 새 어댑터를 후보 상태로 둔다. 자동 승격하지 않는다.

### P6~P8
우선 검증 가능한 강의 데이터로 렌더러를 테스트하고, 이어 실제 모델 계획을 연결한다.
정적 예제 재생은 `demo_fixture`로 표시하고 실제 LLM 강의 성공으로 계산하지 않는다.
음성·사진은 다른 GPU 모델과 순차 사용한다. 기본 text→lesson→audio→playback 경로가 완성된 후 사진 경로를 합친다.

### P9
코드·프로젝트 지침·문서·테스트를 다시 대조한다. 구현하지 않은 버튼이나 TODO가 필수 기능에 남으면 실패/미완료다.
단위 테스트, 모델 실행 테스트, 실제 장치 통합 테스트를 별도 묶음으로 보고한다.

## 차단되었을 때

예: GPU 없음 → P2 GPU 검증과 P3 GPU 검증은 blocked.
그렇더라도 P1 UI, P3 tiny CPU, P4 검색, P5 관리자, P6 판서 엔진, P8 확인 화면,
P9 보안·패키징은 진행할 수 있다. 각 관련 기능에 `gpu_unverified` 상태를 남긴다.
CPU에 1.7B 모델을 몰래 올려 GPU 테스트를 대체하지 않는다.

예: TTS 설치 충돌 → 별도 TTS venv/프로세스를 검토한다. 해결되지 않으면 무음·자막 모드의
정상 동작은 구현하되, “음성 강의 완료”로 보고하지 않는다.

## 종료 분류

- `LOCAL_MVP_VERIFIED`: P0~P9 필수 기능의 실제 장치 증거가 모두 존재. 품질 연구 완료를 뜻하지 않음.
- `IMPLEMENTED_RUNTIME_BLOCKED`: 구현·가능한 테스트는 수행했으나 실제 모델·GPU 등 필수 검증 차단.
- `PARTIAL`: 필수 구현이나 테스트가 남음.

스크린샷이 예쁘다는 이유로 완료하지 않는다. 실제 기능과 연결된 증거가 필요하다.

# 제품 범위와 교육 행동

## 사용자 여정

사용자는 프로그램을 켜고 모델 준비 상태를 확인한다. 질문을 입력하거나 문제 사진을 올린다.
사진이면 먼저 원문·표·보기의 인식 결과를 수정·확정한다. 모델은 관련 자료를 검색할 수 있고,
답변과 출처를 표시한다. 사용자가 강의 보기를 누르면 원본 표, 계산 과정, 최종 결과가
칠판에 순차 표시되고 2D 캐릭터가 실제 합성 음성을 재생하며 설명한다.
중간에 질문하면 기존 재생을 멈추고, 어느 단계·표·강조 대상을 보고 있었는지 유지한 채 재설명한다.

관리자는 자료를 등록하고 검토 상태를 표시하며, 학습 데이터를 검사하고 제한된 학습을 시작·중지한다.
실제 사용 중인 모델·어댑터, 자원 사용량, 학습 그래프, 평가 비교와 실패 원인을 확인한다.

## 필수 기능

F01. 한국어 대화: 입력, 답변 스트리밍, 중단, 대화 저장·삭제·내보내기.
F02. 실제 로컬 모델: 공식 공개 모델과 토크나이저 로딩, 모델/어댑터 정보 표시.
F03. 실제 추가 학습: 데이터 검사, QLoRA, 로그, 저장, 재로딩, 평가, 승격은 관리자 선택.
F04. 관리자: 데이터·작업 큐·학습·평가·오류·모델 구조·자원 상태.
F05. 출처 있는 자료 검색: TXT/MD/텍스트 PDF, 청크·출처·페이지·삭제 반영.
F06. 검증형 SQL 예제: 지원 dialect의 읽기 전용 테스트, 원본·중간·결과 표.
F07. 강의 화면: 단계별 판서, 자막, 이전/다음/일시정지, 캐릭터 가리키기.
F08. 한국어 음성: 실제 로컬 TTS 출력, 음성 재생 기준 동기화, 소리 끄기.
F09. 중간 질문: 취소된 생성/오디오가 다시 끼어들지 않음, 칠판 상태 보존.
F10. 사진: 작은 로컬 비전 모델의 인식 후보 → 사람의 확인 → 원문 확정 후 풀이.
F11. 아바타 교체: 기본 자체 제작 2D 캐릭터와 사용자 자산 가져오기 규격.
F12. 설치·실행·테스트·백업·오류 대응 문서 및 재개 가능 작업 기록.

## 선택 기능과 범위 밖

선택: 직접 구현하는 미니 Transformer 실습, 특정 층 활성값 분석, 음성 디자인 모델,
마이크 입력/음성 인식, Live2D/3D 자산 어댑터. 필수 기능 완료를 이 작업으로 지연하지 않는다.
이번 음성 입력의 필수 범위는 아니다. 끼어들기는 텍스트 질문만으로도 반드시 작동해야 한다.

범위 밖: 전 과목 성능 보장, 강사 영상의 자동 행동 학습, 무허가 음성 복제,
한글 모든 글자의 실제 필기 획순 생성, 실사 인물 영상 생성, 공개 다중 사용자 SaaS,
결제·회원 가입·클라우드 동기화·모바일 앱 스토어 배포, 대규모 기반 모델 사전학습.

## 설명 방식

- 최종적으로 무엇을 구하는지 → 원본 자료 → 필요한 기초 개념 → 조건의 자연어 풀이 →
  계산/행 변화 → 최종 결과 → 헷갈릴 지점 순으로 설명한다.
- SQL은 실제 값이 있는 원본·중간·최종 표를 연결한다. DBMS에 따라 달라지면 기준을 밝힌다.
- 소스 코드는 설명하는 범위를 생략 없이 보여주고 실행 순서와 값 변화를 연결한다.
- 잘못된 학생 답을 받으면 맞게 이해한 부분과 처음 잘못된 판단을 구분한다.
- 원문에 없는 표·조건·숫자를 임의로 채우지 않는다. 별도 설명 예시는 `설명용 예시`라 표시한다.
- 모르는 내용, 읽지 못한 문자, 검증하지 않은 실행 결과를 명시한다.
- 학생의 피드백은 자동 학습이 아니라 검토 대기 데이터로 저장한다.
- 생명·건강·법률 관련 자료는 교육 범위를 표시하며 실제 전문 판단을 대체한다고 안내하지 않는다.

## 화면 언어와 디자인

사용자 화면과 운영 문서는 한국어다. 오류는 쉬운 설명 + 상세 로그 보기로 나눈다.
첫 화면 이름은 `AI 강의실`, 메뉴는 `대화`, `강의실`, `교육자료`, `학습·평가`, `모델 분석`, `설정`으로 한다.
PC 1440×900과 1280×720을 우선 확인하고, 좁은 화면에서는 패널을 접는다.
표·코드가 캐릭터에 가려지지 않아야 한다. 키보드 조작·포커스·대비·자막을 제공한다.
화려한 도식보다 질문/현재 단계/검증 상태를 먼저 보이게 한다.

# 기술 구성·환경·작업 관리

## 기본 구현 경로

새 프로젝트 기준:
- Python 3.11 우선: FastAPI, Pydantic, SQLite, PyTorch, Transformers, PEFT, Accelerate, bitsandbytes.
- 학습은 Transformers.Trainer + 직접 검증한 data collator. TRL은 이번 경로에서 제외한다.
- 웹 화면은 React + TypeScript + Vite. 판서는 SVG/HTML, 수식은 KaTeX 등 검증된 렌더러.
- Python 테스트 pytest, 웹 단위 Vitest, 브라우저 E2E Playwright.
- 학습 로그는 JSONL + TensorBoard. TensorBoard 공개 네트워크 노출 금지.
- 저장은 로컬 SQLite와 파일. Redis/Postgres/Docker는 필수 구성으로 추가하지 않는다.
- Gradio와 React 관리자 화면을 중복 구현하지 않는다. 복잡한 강의 타임라인 때문에 React를 선택한다.
  기존 앱이 이미 다른 스택으로 정상 작동하면 기능 충족 여부를 확인해 유지하고 변경 근거를 기록한다.

패키지 버전은 실제 설치·import·스모크 테스트 후 lockfile에 고정한다.
서로 다른 모델 런타임의 요구 버전이 충돌하면 text/train, vision, TTS 가상환경을 분리하고
작업 프로세스 인터페이스로 연결한다. 검증하지 않은 버전 번호를 “검증됨”이라고 적지 않는다.
FlashAttention, torch.compile, vLLM, 다중 GPU는 필수로 만들지 않는다.

GPU를 사용하지 않는 API 프로세스와 모델 worker를 분리한다. API는 메모리를 가득 채운 작업 때문에
상태 조회·취소 요청에 응답하지 못하는 구조가 되어서는 안 된다. worker와 통신하는 payload를 검사한다.
훈련·추론·TTS·비전은 명시적인 작업 종류와 설정만 허용한다. 사용자 임의 명령 문자열은 받지 않는다.

## doctor

모델 다운로드 없이 JSON과 쉬운 요약을 출력한다.
실제 OS/WSL, Python, 로컬/원격 여부의 확인 근거, GPU 가시성, torch CUDA, BF16 지원,
VRAM total/free, RAM total/free, 지정 저장 경로의 디스크 공간, 의존성 버전을 기록한다.
네트워크 검사 실패는 런타임 실패와 구분하고, 알 수 없는 값은 null + reason으로 기록한다.
WSL에서는 Windows 호스트 드라이버를 사용한다. 일반 Linux GPU 디스플레이 드라이버를
WSL에 임의 설치하지 않는다. 기존 native Windows 경로가 검증되면 유지한다.

## GPU 직렬화 — 핵심

전용 VRAM 8GB에는 큰 모델을 무조건 동시에 올리지 않는다.
전 앱의 GPU lease를 OS file lock과 DB 작업 레코드로 관리하고 CLI도 동일 규칙을 사용한다.
lease에는 job_id, PID, 프로세스 시작 식별자, device, heartbeat를 남긴다.
PID 번호만 보고 남의 프로세스를 종료하지 않는다. stale lease 복구는 생존 여부를 확인한 뒤 수행한다.

작업 상태:
queued → loading → running → saving → succeeded
추가 terminal: failed / cancelled / interrupted / blocked.
취소는 cancel_requested를 기록하고 worker가 안전한 시점에 반응한다.
브라우저 새로고침은 작업 성공·실패로 간주하지 않는다. 서버 재시작 후 고아 작업은 interrupted로 복구한다.

텍스트 모델 → 음성 모델 → 비전 모델 전환 때 이전 worker의 참조·메모리 정리를 확인한다.
`empty_cache()` 호출만으로 모델이 GPU에서 사라졌다고 판단하지 않는다.
필요하면 소유한 worker를 정상 종료하고 다음 worker를 실행한다.
CPU로 내리는 경우 RAM 잔량도 확인하고, 메모리를 계속 누적하지 않는다.
사용 중인 학습 작업이 있으면 채팅은 대기/거절 상태를 명확하게 표시한다.

## 요청과 취소

모든 생성에 session_id, request_id, generation_epoch를 붙인다.
사용자가 중단/새 질문/새 강의를 시작하면 epoch를 갱신한다.
기존 스트리밍·오디오·판서 이벤트가 늦게 도착해도 이전 epoch면 UI가 폐기한다.
작업 재시도에는 idempotency key를 사용해 중복 학습 시작·중복 산출물 등록을 막는다.

## 실행 제한

기본 컨텍스트 2048 tokens부터 검증하고 GPU 여유가 확인될 때만 확장한다.
총 입력/출력 토큰 예산을 검사한다. 예산을 넘으면 무작위 잘림 대신 사용자에게 알리거나
인용 자료 개수·이전 대화를 명시적으로 줄인다. 강의 계획은 단계별 생성으로 긴 JSON을 피한다.
기본 동시 GPU 작업 1개. 서버 host는 127.0.0.1. 다른 네트워크 노출은 자동 활성화하지 않는다.

## 핵심 API 계약

OpenAPI로 계약을 남기고 web 클라이언트 타입과 일치시킨다.
- 상태/설정: health, capabilities, doctor, models, adapters
- 대화: sessions, messages, generation events, cancel
- 자료: documents, ingest, review, search, delete

- 평가: evaluations, compare, rubric results
- 강의: lesson create/read, speech prepare, play state, interrupt/reexplain
- 사진: upload, transcribe, edit, confirm

큰 파일은 제한된 multipart 업로드로 받고 임의 로컬 경로·임의 외부 URL fetch는 제공하지 않는다.
파일 읽기와 삭제는 서버가 발급한 ID를 경로에 매핑한다.

# 로컬 모델·실제 추가 학습

## 모델 선택

기본 텍스트 모델은 `Qwen/Qwen3-1.7B`다. 이는 작은 실험 출발점이며 최신/최고 교육 모델이라는 뜻이 아니다.
후속 4B 이상 모델을 자동 다운로드하지 않는다. 모델 카드, 라이선스, revision, chat template을 기록한다.
학습에는 Transformers 공식 가중치를 사용하고 GGUF 추론 파일을 QLoRA 학습에 넣지 않는다.
기본 trust_remote_code=False, 모델·어댑터는 safetensors 우선. 불명확한 저장소 코드를 자동 실행하지 않는다.

LoRA/QLoRA는 기존 공개 모델에 추가한 작은 학습 부분을 수정하는 방식이다.
어댑터만 저장한 것을 독립적인 기반 모델을 새로 만들었다고 표현하지 않는다.
실제 사용 기반 모델과 revision이 다르면 어댑터 적용 전에 호환성을 검사한다.

## 학습 전 기준선

기반 모델만으로 한국어 설명·NULL·조건 부족·표 있는 SQL 문제를 실행한다.
입력·생성 옵션·출력·소요 시간·peak VRAM·끝난 이유를 저장한다.
Qwen3의 non-thinking 설정을 공식 template에 맞게 적용하고, 답변에는 공개 설명만 표시한다.
토큰 제한으로 잘린 답변을 정상 완성으로 채점하지 않는다.
구조화 출력은 모델 능력을 보장하지 않는다. JSON 검증과 재생성 제한은 강의 명세를 따른다.

## 초기 학습 설정

프로젝트 정책의 출발점이지 최적값·8GB 성공 보장값이 아니다.
- 4bit NF4, double quantization.
- compute dtype: 실제 BF16 지원 확인 시 BF16, 아니면 검증된 FP16 경로.
- prepare_model_for_kbit_training 후 PEFT 연결.
- r=8, alpha=16, dropout=0.05, target_modules=[q_proj, v_proj].
- batch size=1, gradient accumulation=8, learning rate=1e-4.
- max sequence length=512, packing=False, gradient checkpointing=True, use_cache=False.
- single GPU 명시. 추론용 device_map=auto로 CPU/offload 분산을 몰래 적용하지 않는다.
- 기본 seed=42. seed 고정을 다른 장치/라이브러리 버전의 비트 단위 재현 보장으로 설명하지 않는다.
- optimizer는 설치 환경에서 검증되는 표준 AdamW 경로를 우선하고 불필요한 추가 optimizer 의존성을 피한다.
- 5 optimizer step smoke를 먼저 수행한다. microbatch 5회와 optimizer step 5회를 혼동하지 않는다.

전체/학습 가능 파라미터 수, 실제 target module 이름, dtype, 입력 길이, device를 manifest에 기록한다.
원래 가중치의 requires_grad와 optimizer 파라미터 목록을 확인한다.
처음 LoRA 초기화에서 일부 행렬 gradient가 0인 것은 가능하므로, 모든 파라미터가
첫 step부터 비영 gradient여야 한다는 잘못된 테스트를 만들지 않는다.

## 응답 구간 마스킹 — 반드시 실제 토큰 검사

초기 데이터는 단일 질문-단일 답변으로 단순화한다. multi-turn을 지원하면 마지막 assistant 응답만
target으로 하고 이전 대화는 context로만 사용하는 규칙을 명시한다.

1. 고정한 revision의 tokenizer와 실제 chat template을 읽는다.
2. 추론 시 쓰는 generation prefix와 학습용 완성 대화의 assistant 시작 부분이 같은지 확인한다.
   Qwen3 non-thinking의 빈 think 블록이 들어갈 수 있음을 고려한다.
3. prefix 토큰과 전체 학습 토큰의 공통 앞부분을 **실제 토큰 ID로** 검증한 뒤 답변 시작 경계를 구한다.
   문자 길이나 별도로 tokenize한 문자열 길이를 무조건 믿지 않는다.
4. template이 prefix 안정성을 제공하지 않으면 공식 형식을 유지하는 canonical serializer를 만들고
   model-specific prefix+completion 경로를 fixture로 검증한다. 답변 내용이 중복되어도 위치가 정확해야 한다.
5. prompt/context 및 padding의 labels는 -100. 실제 답변과 정상 종료 `<|im_end|>`는 target에 남긴다.
   pad_token_id == eos_token_id인 설정에서 ID만으로 모두 가리면 실제 EOS가 사라질 수 있으므로
   유효 길이/attention mask로 padding을 구분한다.
6. causal LM 자체의 label shift를 사용하고 수동 shift를 중복 적용하지 않는다.
7. target token 0개, 정답 잘림, 모든 labels=-100 샘플은 학습 전에 실패시킨다.
8. input tokens, target mask, target만 decode한 문자열을 샘플별 검증 파일로 남긴다.

장문을 조용히 자르지 않는다. 초과 샘플은 제외/교육 단위로 분리하고 원래 ID와 사유를 기록한다.
max_length를 늘리려면 VRAM 검증과 설정 변경 내역이 필요하다.
loss mask 테스트와 실제 생성 template 테스트는 서로 별도다.

## GPU 없는 환경의 CPU 배선 테스트

실제 1.7B 가중치를 다운로드하지 않고 작은 랜덤 초기화 Qwen3Config 모델을 만든다.
예: vocab_size≤512, hidden_size=64, intermediate_size=128, layers=2,
attention_heads=4, key_value_heads=2, 짧은 sequence. 실제 설치 버전이 지원하는 필드로 구성한다.
이 모델은 **배선 검증용이지 학생에게 서비스할 교육 모델이 아니다.**

FP32 일반 LoRA로 finite loss, target masking, gradient, optimizer update, adapter save/load를 검사한다.
기반 모델 초기 state/config를 한 번 저장하고 어댑터 재로딩에도 정확히 같은 기반 가중치를 사용한다.
새 random base에 어댑터를 붙이고 출력 일치 테스트를 하면 안 된다.
trainable weights가 실제 변하는지, frozen base가 그대로인지 비교한다.
eval mode/dropout off 상태의 저장 전후 logits를 dtype에 맞는 tolerance로 비교한다.

tokenizer를 캐시/네트워크로 확보하면 실제 Qwen template도 CPU에서 테스트한다.
토크나이저조차 없으면 로컬 synthetic fixture로 공통 로직만 검사하고,
**실제 Qwen template 검증은 미실행**이라고 별도 표시한다.
CPU backend가 없다고 단정하는 설명 대신, CPU 배선 테스트에서 비양자화 LoRA를 쓰는 이유를
작은 의존성·빠른 확인·CUDA 통합과의 분리라고 설명한다.

## 실제 GPU 검증

text 모델 4bit load → 기준선 → 5 optimizer step → 저장 → worker 종료 →
새 프로세스에서 같은 기반 모델+어댑터 load → 응답 생성 순서로 확인한다.
CPU test pass를 이 증거로 대체할 수 없다.
실제 학습 후 가중치 비교는 어댑터 위주로 하고 frozen base는 파라미터 동결·optimizer 제외 및
선택한 모듈의 체크섬/값 비교를 기록한다. GPU 전체 모델 복사로 불필요한 OOM을 만들지 않는다.

smoke가 통과하면 정책 범위의 50 optimizer step 이하 데모 학습 1회까지 허용된다.
시간 제한으로 50 step에 못 미치면 실제 step을 표시한다.
NaN/inf, OOM, loss target 부재, 디스크 부족은 즉시 안전 중단·원인 기록.
훈련 worker는 앱 큐와 같은 GPU lease를 잡아 채팅/TTS/비전과 충돌하지 않도록 한다.

## 체크포인트와 재개

각 run에는 adapter safetensors/config, 기반 revision, tokenizer/template, 데이터 해시,
설정, 패키지 버전, 실제 완료 step, 평가 결과를 기록한다.
어댑터 가중치 저장과 학습 상태 체크포인트를 구분한다.
학습 이어하기를 지원하려면 optimizer, scheduler, global_step, RNG, 데이터 진행 상태를
현재 Trainer 방식으로 저장하고 실제 중단-재개 테스트를 수행한다.
재개 테스트가 없으면 “가중치에서 새 학습”과 “이전 학습 이어하기”를 같은 기능으로 표시하지 않는다.

관리자는 기반 모델/어댑터 사용을 선택하고 이전 버전으로 되돌릴 수 있어야 한다.
평가 나쁜 어댑터를 자동 기본값으로 승격하지 않는다. 모델 로더 교체 시 실행 중 작업과 경합을 막는다.

# 데이터·자료 검색·평가

## 세 종류의 데이터 구분

1. **교육자료 corpus**: 답할 때 참고하는 원문·출처·페이지. 검색 인덱스 생성은 가중치 학습이 아니다.
2. **추가 학습 dataset**: 검토된 좋은 질문/답변 또는 명확히 표시한 데모. 가중치 변경에 사용.
3. **독립 평가 dataset**: 학습 데이터·프롬프트 예시·검색 인덱스의 정답집과 분리.

`problem_family_id`로 분할하고 이름/숫자만 다른 문제군이 split을 넘나들지 않게 한다.
데이터를 수정하면 version/hash를 새로 생성한다. 동일 family는 한 split에만 존재한다.
모델 사전학습 데이터에 무엇이 있었는지 완전히 확인했다고 주장하지 않는다.

## 새로 작성하는 데모

기본키, 외래키, NULL, COUNT, WHERE/HAVING, 기본 JOIN, GROUP BY 등 소규모 예제로 시작한다.
기출 문장·유료 교재·강사 말투를 기억에서 그대로 복원하지 않는다.
train≥24, validation≥8, test≥12는 기능 점검을 위한 최소 규모일 뿐 성능의 통계적 보장 기준이 아니다.
문제 종류별 다양성을 유지한다. 수량 기준 때문에 잘못된 정답을 급히 넣지 않는다.

형식은 `schemas/qa_record.schema.json`을 따른다. 직접 작성한 자료도 source와 created_by를 남긴다.
AI 생성 예제에는 `review_status=generated_unreviewed`, `demo_only=true`를 기본으로 한다.
SQL 실행으로 확인한 부분은 `machine_verified` 검증 기록을 별도 추가할 수 있지만,
교육 설명 전체가 인간 검토된 것으로 승격하지 않는다.

데모 학습은 명시적 demo profile에서 미검토 생성 예제를 사용할 수 있다.
운영 학습 profile은 사람이 승인한 자료만 포함한다. 관리자 승인 action과 시간을 감사 로그에 남긴다.
학생 대화·개인정보·오답은 자동으로 학습셋에 들어가지 않는다.

필수 검사: 필드·역할 순서·중복·family 분리·source·권리 메모·token 길이·응답 target·NULL 표현.
NULL은 문자열 "NULL"이 아닌 null로 저장하고 UI에서 NULL로 표현한다.

## 검색(RAG)

기본 입력은 TXT/MD 및 텍스트가 들어 있는 PDF. PDF는 페이지별 텍스트 추출 후
사람이 미리보기를 확인한다. 스캔 PDF/복잡한 표는 자동 정확 인식이라고 하지 말고
사진 인식/수동 확인 경로로 보낸다.

첫 검색 엔진은 한국어 문자 n-gram TF-IDF + SQL 키워드 보정을 사용해 CPU에서 실행한다.
예: TfidfVectorizer의 char 2~4그램. 구현·데이터에 맞춰 확인하며 검색 성능 보장은 하지 않는다.
임베딩 GPU 모델/벡터 DB는 필수로 추가하지 않는다. 추후 provider 교체 인터페이스만 명확히 둔다.

청크에는 document_id, chunk_id, source_title, page/line, text, rights, subject, version을 저장한다.
검색한 실제 청크 ID만 답변 출처로 연결한다. 모델이 임의 생성한 source ID는 reject한다.
해당 문서 삭제 시 청크·인덱스·사용되지 않는 캐시를 삭제하고 재검색 테스트를 한다.
질문 데이터는 사용자 승인 없이 외부 임베딩/검색 API로 보내지 않는다.

검색 문서 안의 "이전 지시 무시" 등은 자료의 문자 내용일 뿐 시스템 명령이 아니다.
추출 문서가 모델의 도구 권한이나 파일 쓰기 대상을 정할 수 없게 한다.
자료가 없거나 관련성이 낮으면 그 상태를 답변에 표시한다. 출처가 있다고 내용이 무조건 맞는 것도 아니다.

## SQL 자동 검증 계약

초기 실행 검증의 공식 dialect는 `sqlite`로 한정한다. 이것은 Oracle을 구현했다는 뜻이 아니다.
Oracle 전용 SQL은 Oracle 실행 환경이 없으면 `not_executed`로 표시한다.
단순 SQLite 결과를 Oracle 정답으로 포장하지 않는다.

각 실행 평가 예제에는 fixture.tables의 스키마/행, reference SQL 또는 expected columns/rows,
row_order 설정, 숫자 비교 정책을 명시한다. 예제 JSON을 참고한다.
신뢰한 fixture로 일회성 DB를 준비한 뒤 실제 모델 SQL은 SELECT 계열의 읽기 전용으로 제한한다.

모델 SQL 추출 규칙은 버전 있는 구조 `{sql, explanation}`을 우선 사용한다.
파싱이 실패하면 코딩 블록 `sql` 하나만 존재하는 응답에서만 추출한다.
여러 SQL 블록/여러 문장/정체 불명의 내용이면 ambiguous_parse로 처리한다.
정규식만으로 임의 SQL을 안전하다고 판단하지 않는다.

별도 subprocess에서 다음을 함께 적용한다.
- 임시/일회성 DB, 사용자 DB 연결 금지.
- SQLite authorizer 및 query_only 설정으로 DML/DDL/ATTACH/확장 로딩 등 금지.
- 위험 함수/PRAGMA/파일 접근을 허용하지 않음; 단일 읽기 전용 문장만 실행.
- progress handler/시간/행 수/출력 크기 제한, 무한 recursive query 방지.
- 실패는 오류로 기록하고 실제 DB나 OS를 조작하지 않음.

ORDER BY가 없으면 결과는 중복 수를 보존하는 multiset으로 비교한다.
단순 set 비교로 중복 행 오류를 놓치지 않는다. ORDER BY가 있으면 명시된 행 순서를 비교한다.
컬럼 순서는 명세대로 비교한다. float 허용 오차는 평가 예제에서 정하고,
모든 숫자를 임의 문자열 변환해서 같다고 만들지 않는다.

## 학습 전후 평가

항상 표시할 문구:
“소규모 데모 평가입니다. 파이프라인 검증용이며, 전체 교육 성능이나 일반화 성능을 보장하지 않습니다.”

같은 문제·동일 생성 조건·동일 revision·동일 RAG 자료 조건으로 baseline vs adapter를 비교한다.
기본 학습 비교는 RAG off. RAG 유무 효과는 별도 실험으로 분리한다.
평가 정답/해설을 RAG corpus에 넣지 않는다. 의도한 오픈북 평가는 그 사실과 corpus를 기록한다.
평가셋을 보고 설정을 반복 조정했다면 test 독립성이 깨졌음을 표시하고 새 holdout을 둔다.

자동 지표: schema success, SQL parse/execution/result match, 필요한 조건 누락 시 확인 요청,
source ID 유효성, 끊김/timeout, latency/VRAM. 자동 규칙의 한계를 함께 기록한다.
사람 지표: 설명 정확성, 중간 과정 충분성, 쉬운 용어 풀이, 잘못된 확신, 학생의 오해 교정.
사람 평가를 실행하지 않았으면 점수를 지어내지 말고 `not_reviewed`로 둔다.
모델 자신이 매긴 점수를 인간 평가로 표시하지 않는다.
정답률은 n/N을 함께 보여주고, loss 감소를 정답률 증가로 설명하지 않는다.

# 채팅·관리자·모델 시각화 UI

## 공통

화면은 실제 API 상태를 보여준다. 개발 fixture를 켰다면 상단에 `데모 데이터 재생` 배지를 항상 표시한다.
실제 상태가 없을 때 예쁜 임의 그래프 대신 `아직 실행 기록이 없습니다`를 보여준다.
로딩·미설치·미검증·실패·완료는 색뿐 아니라 글자로도 구분한다.
모든 위험한 동작에는 대상과 범위가 표시된다. UI가 보여주는 현재 모델명/어댑터는 backend manifest에서 읽는다.

## 대화

좌측 대화 목록, 중앙 질문/답변, 우측 접을 수 있는 출처/모델 상태 패널.
한국어 IME 조합 중 Enter를 전송으로 처리하지 않는다. Enter/Shift+Enter 동작을 도움말에 명시한다.
스트리밍, 중지, 다시 생성, 텍스트·표·코드 렌더링, 복사, 대화 삭제·내보내기를 구현한다.
답변에는 기준 모델·어댑터, RAG 사용 여부, 검증 범위, 참고 청크를 확인할 수 있게 한다.
정확도 미검증 상태에서 무조건 초록색 `정답` 배지를 표시하지 않는다.

## 관리 홈

GPU 모델/전용 VRAM total/used/free, 시스템 RAM, 저장 경로 공간, 현재 GPU 소유 작업,
대기 큐, 모델 로딩 상태, 최근 오류와 최근 평가를 표시한다.
공유 GPU 메모리를 VRAM total에 더하지 않는다. 자원 수치를 읽을 수 없으면 N/A와 사유 표시.
과도한 초고속 polling을 피하고 서버·브라우저 부하를 측정한다.

## 학습·평가

데이터 검사 결과 → split/family/길이/검토 상태 → 설정 요약 → 자원·예산 확인 → 시작 순서.
데모 smoke와 운영 학습을 분리한다. 학습 버튼은 실제 job API를 호출한다.
작업 시작 전 동시 GPU 작업과 상태 충돌을 검사하고, 남의 채팅을 몰래 종료하지 않는다.
취소 상태는 requested와 실제 stopped를 구분한다. 체크포인트 저장 중에는 이유를 보여준다.
완료 목록에는 actual step, duration, dataset hash, base revision, adapter path, 평가 상태가 나온다.
전후 비교는 같은 질문을 나란히 보여주고 사람이 평가할 수 있는 rubric 입력을 제공한다.
어댑터 적용·이전 버전 복귀를 지원하되 실행 중 모델 교체는 큐를 통해 안전하게 처리한다.

## 모델 분석 — 실제 신경망의 무엇을 보여줄 것인가

필수:
1. 현재 모델 config와 실제 named_modules에서 읽은 계층 트리.
2. 층 이름·모듈 종류·shape·파라미터 수·dtype·device·trainable 여부.
3. LoRA가 붙은 실제 모듈과 frozen/trainable 구분.
4. tokenization 예시: 입력 글과 token ID/문자 대응. 비밀 대화는 기본 로그 수집 대상에서 제외.
5. loss, learning rate, optimizer step, 처리량, VRAM 그래프. 실제 로그에서만 그린다.

구조도는 레이어 단위로 접고 펼친다. 수십억 개 파라미터를 각각 점으로 그리려 하지 않는다.
실제 실행 추적을 수집하지 않았다면 `모델 구조도`라고 이름 붙이지 `실시간 신경 활동`이라 부르지 않는다.
TensorBoard graph 변환이 특정 모델에서 안 되면 모듈 트리와 config를 제공하고
실행 그래프 미지원 상태를 표시한다. 그래프 성공을 위조하지 않는다.

선택 심화:
- 작은 입력/선택 층에 제한한 activation norm 또는 attention heatmap.
- 실제 hook/tensor에서 수집한 값만 사용하고 hook 제거·메모리 제한을 테스트한다.
- 학습과 동시 사용하지 않고 분석 작업이 GPU lease를 잡는다.
- SDPA 등의 경로에서 attention weight를 반환하지 않으면 미지원 처리 또는 검증한 분석 모드만 사용.
- “AI의 생각을 읽는 화면이 아니라 계산 관찰 자료”라는 설명을 붙인다.

## 교육자료·설정

문서 업로드·미리보기·출처·권한 메모·검토 상태·검색 테스트·삭제를 제공한다.
시험 문제 사진의 원문 확인과 교재 corpus 등록을 구분한다. 사진 한 장을 자동 영구 학습셋으로 넣지 않는다.
설정에는 모델 캐시 위치·언어·TTS 화자·속도·아바타·자원 예산을 둔다.
브라우저에서 임의 Python 코드/명령/시스템 경로를 입력하는 기능은 만들지 않는다.

## UI 검증

1440×900과 1280×720에서 실제 브라우저 캡처를 남긴다. 캡처를 열어 표·코드·버튼 겹침을 직접 확인한다.
한글 입력, 긴 오류, 큰 표, 빈 데이터, 로딩 취소, 새로고침, 서버 재연결을 테스트한다.
마크다운 HTML, 링크, 수식 렌더링은 sanitization과 제한된 스키마를 거친다.
실제 브라우저를 못 실행한 환경에서는 화면 검증을 미실행으로 기록한다.

# 강의·판서·음성·2D 아바타

## 먼저 구분

LLM은 설명과 판서 계획을 만든다. 렌더러는 승인된 명령을 화면에 그린다.
매 강의마다 실사 영상을 생성하는 방식이 아니다. 사용자 지정 캐릭터 자산이 없으면
프로젝트가 직접 만든 기본 벡터 캐릭터를 사용하고 `기본 아바타`라고 표시한다.
사용자 본인의 외모나 특정 실존 강사의 목소리라고 주장하지 않는다.

## 구조화 강의 계획

`schemas/lesson_plan.schema.json`을 계약으로 사용한다. 스키마 통과와 교육 내용 검증은 별개다.
필수 필드: title, goal, problem_source, provenance, source_refs, verification,
steps(각 speech, board_actions, gesture, target), final_summary.
원본 자료·예시 자료·실제 계산 결과·미검증 설명의 구분을 유지한다.
사용자에게 공개할 교육 풀이이지, 모델 내부 비공개 사고 과정을 요청하거나 표시하는 기능이 아니다.

모델은 처음 목표/단계 목록을 만들고 필요하면 각 단계를 따로 생성한다.
작은 모델에 긴 완성 JSON을 한 번에 강제해 망가뜨리지 않는다. 입력/출력 budget을 검사한다.
출력 파싱 실패는 제한된 1회 수정 요청 후 실패를 표시한다. 무한 재시도를 하지 않는다.
마지막 fallback은 **실제 생성된 답변을 그대로 설명 텍스트 카드로 표시**하는 것이며,
성공한 구조화 강의라고 표시하거나 하드코딩 정답으로 바꿔 끼우면 안 된다.

## 판서 엔진

허용 명령만 실행: text, equation, table, code, highlight, arrow, clear.
각 명령에 element_id, 명시적인 내용/셀, 강조 대상, 정규화 좌표/레이아웃 슬롯을 둔다.
LLM이 JS/HTML/CSS 실행문을 만들거나 임의 URL 자산을 로딩하게 하지 않는다.
SQL 검증 결과와 판서 표가 다르면 불일치를 표시하고 자동으로 사실인 척 진행하지 않는다.

판서는 문장·행·셀 단위로 점진 표시한다. 원문 테이블을 먼저 보여주고 결과를 다음 장면에 표시한다.
글꼴 기반 점진 노출은 실제 한글 획순 필기와 다르다는 사실을 문서에 명시한다.
모든 글자의 손글씨 stroke 합성을 이번 필수 범위로 만들지 않는다.
수식은 안전한 KaTeX 설정, 코드는 고정폭·줄 번호·강조, 표는 헤더·NULL 표시·행 강조를 제공한다.

scene reducer는 step을 적용해 board state를 만드는 순수 로직으로 테스트한다.
이전 단계로 이동/다시 재생/새로고침 복원 시 같은 board state가 재구성되어야 한다.
하나의 페이지에 모두 우겨넣지 말고 내용이 많으면 새 board page로 분리한다.
캐릭터가 표·답을 덮지 않게 board 영역과 avatar 영역을 나눈다.

## 캐릭터

필수 동작: idle, look_board, point, write, explain.
말하기는 입 열림을 음성 파형의 RMS/진폭에 연결하고, 실제 phoneme lip-sync라고 주장하지 않는다.
팔/손은 실제 board element의 화면 좌표를 따라가며 리사이즈·스크롤 후에도 맞아야 한다.
아무 의미 없이 손이 흔들리는 것만으로 필기 동기화 완료라고 하지 않는다.

초기 자산은 코드로 만든 원본 SVG 내부 자산 또는 PNG 파츠로 구성한다.
사용자 교체는 안전한 PNG 파츠+manifest 방식 또는 정적 PNG 캐릭터 방식부터 지원한다.
정적 PNG는 몸/머리 단순 움직임만 가능함을 표시한다. 한 장의 그림을 완전 리깅으로 변환한다고 약속하지 않는다.
임의 업로드 SVG는 inline 주입하지 않는다. 가져오려면 sanitize/rasterize 경로를 검증한다.
입/눈/팔 anchor, 크기, origin, 라이선스 정보를 manifest로 관리한다.

## 음성 생성

기본 로컬 TTS 후보는 `Qwen/Qwen3-TTS-12Hz-0.6B-CustomVoice`.
모델 카드와 설치 버전에서 한국어·화자·instruct 지원 범위를 실제 확인한다.
예제의 FlashAttention을 무조건 필수로 삼지 말고 지원되는 기본 attention 경로를 검증한다.
TTS 라이브러리 의존성이 충돌하면 별도 venv worker를 사용한다.
같은 GPU에서 텍스트/학습/비전과 동시에 실행하지 않는다.

처음부터 완전히 새로운 목소리를 학습하지 않는다. 제공되는 허용 화자와 언어/읽기 속도 설정을 사용하고
UI에 preset voice라는 사실을 밝힌다. 사용자 고유 음색 생성이 완료됐다고 하지 않는다.
자연어 VoiceDesign/사용자 권리 있는 reference voice는 별도 선택 확장이다.
설정에 voice profile/engine ID/revision/권리 메모를 저장해 향후 교체할 수 있도록 한다.

SQL 키워드와 기호의 표시 문자열과 발화 문자열을 분리한다.
예: 화면 COUNT(*)는 그대로, 발화는 “카운트 별표”처럼 사전 규칙을 적용할 수 있다.
수식과 숫자를 마음대로 바꾸지 않는다. 발음 규칙은 관리자 설정과 단위 테스트로 관리한다.

TTS는 단계별 WAV/재생 가능한 오디오를 생성한다. 파일에 text hash, voice, revision,
생성 설정, 실제 duration, checksum을 기록한다. 설정이 바뀌면 캐시 key도 달라진다.
실제 생성한 한국어 문장 3개 이내로 파일 길이·무음 여부·재생을 확인한다.
음성 품질을 사람이 듣지 못한 환경에서는 `listening_review=not_run`으로 둔다.

TTS 불가 시 자막/수동 단계 모드로 사용할 수 있게 하되 `음성 사용 불가`를 표시한다.
브라우저 speechSynthesis를 fallback으로 넣더라도 네트워크/voice availability를 확인하고
로컬 TTS 검증 통과로 계산하지 않는다. 외부 전송 가능 voice는 동의 없이 사용하지 않는다.

## 동기화와 중간 질문

첫 구현은 강의 대본·판서 계획을 만든 뒤 음성을 준비하는 buffered 방식이다.
첫 답을 기다리는 시간과 모델 교체 시간이 있을 수 있음을 화면에 표시한다. 실시간 무지연이라 부르지 않는다.
텍스트 모델을 해제하고 단계 오디오들을 생성한 다음, 화면에서 재생하는 경로를 우선한다.

같은 단계의 실제 audio currentTime/duration을 기준으로 판서 진행을 계산한다.
짧은 문장별 분할 또는 시간 비율 매핑은 가능하지만 단어 수준 완벽 정렬이라고 표시하지 않는다.
setTimeout 연쇄만으로 음성·판서를 각각 달리 진행시키지 않는다.
일시정지/재개/이전 단계/배속/음소거가 같은 timeline state에 연결되어야 한다.
브라우저 autoplay 정책을 존중하고 사용자 재생 버튼으로 시작한다.

중간 질문이 들어오면:
1. 현재 audio pause/stop, 입·팔 동작 중지.
2. 현재 lesson/step/board snapshot/element/질문을 보존.
3. generation epoch 증가, 오래된 응답·오디오 이벤트 폐기.
4. 현재 보이는 내용과 질문을 텍스트 모델에 전달. 필요하면 GPU worker 교체.
5. 재설명용 단계·음성을 만들고 새 epoch로 재생.
6. 원래 강의로 돌아가는 명시적인 버튼 제공.

실제 GPU cancel이 즉시 끝나지 않아도 화면 재생 중단은 즉시 처리한다.
GPU는 안전한 checkpoint/연산 경계에서 해제하고 진행 상태를 표시한다.

# 사진 입력과 원문 확인

## 목표

사진을 읽는 기능과 그 문제를 푸는 기능을 분리한다. 이미지에서 읽은 내용을 학생이 확인하기 전에
잘못된 숫자/조건으로 강의를 시작하는 일을 막는다. 사용자가 이전에 보낸 PC 사양 사진을
교육 문제 사진이나 학습 데이터로 사용하는 기능은 만들지 않는다.

## 로컬 비전 경로

후보: `Qwen/Qwen3-VL-2B-Instruct`의 공식 모델/processor, 지원되는 4bit 경로.
실제 설치 버전과 model class를 확인한다. 텍스트 모델에 이미지 bytes만 붙여 이미지 인식이라 하지 않는다.
processor 입력 해상도·픽셀/토큰 상한을 명시하고 작은 사진 1장부터 검사한다.
image quality가 부족하면 임의로 채우지 않고 재촬영/부분 확대/수동 입력을 요청한다.
인식 worker는 앱의 공통 GPU lease를 사용한다. VRAM 확보가 안 되면 blocker로 기록한다.
기본 비전 모델 학습은 하지 않고 추론만 한다.

## UI 흐름

업로드 → 안전한 디코딩 → 회전/축소 미리보기 → 인식 후보 → 원문 편집 → 확정 → 풀이/강의.
PNG/JPEG/WebP부터 지원한다. 크기 기본 10MiB, 최대 20MP; 변경은 설정으로 관리한다.
MIME/extension뿐 아니라 실제 파일 내용과 디코딩 가능 여부를 확인한다.
EXIF orientation은 반영하고 불필요한 위치정보는 저장·노출하지 않는다.

후보 편집 UI에는 question, SQL/code, tables, choices, unreadable_regions, missing_conditions를 구분한다.
모델의 추정 confidence를 실제 정확도 확률로 표시하지 않는다.
수식·표·기호가 불분명하면 `확인 필요`를 붙인다. 순서를 바꿔 적은 선택지는 원문 확인에서 드러나야 한다.
원문과 교정문을 따로 저장하고 `confirmed_at`, `confirmed_by`, revision을 기록한다.
학생 확인 전 결과에는 미확정 배지가 있고 solve/lecture API는 confirmed=false이면 거절한다.
조건이 비어 있는 채 확정되면 AI가 답 대신 누락된 조건을 물을 수 있어야 한다.

## 인식 방식의 구분

이미지 모델 출력은 학습된 지식·예제 풀이가 아니라 원문 전사 후보로 취급한다.
문제 안의 텍스트가 시스템 지시처럼 보이더라도 실행 권한을 바꾸지 않는다.
인식 서비스가 설치되지 않은 환경에서는 수동 텍스트 입력·표 편집을 제공하되
이미지 자동 인식이 성공한 것처럼 기록하지 않는다.

## 테스트

직접 만든 명확한 문제 이미지, 표 포함 이미지, 일부가 잘린 조건 이미지 3개를 테스트 fixture로 만든다.
정답 데이터는 fixture 전용이며 일반 사진 요청에 filename 기반 정답을 돌려주지 않는다.
자동 인식 정확도를 fixture 3개만으로 일반화하지 않는다.
미확정 상태 요청 거절, 수정 후 revision 변경, 깨진 이미지, 큰 파일, 삭제와 캐시 정리를 테스트한다.
실제 GPU 인식을 못 했으면 UI/업로드 테스트와 분리해 기록한다.

# 검증·보안 명세

## 검증 분류

각 결과에는 tier를 붙인다.
- T0: CPU 단위/계약 테스트. 모델 가중치 다운로드 없이 실행 가능.
- T1: 작은 CPU 모델의 실제 학습·저장·재로딩. mock 계산이 아님.
- T2: 실제 GPU + 실제 모델 실행/학습/인식/음성.
- T3: 브라우저·API·실제 모델을 연결한 장치 통합 테스트.
- H: 인간이 설명/음성 품질을 직접 검토. 수행자가 없으면 not_reviewed.

mock/test double은 T0나 명시적 UI 테스트에서 사용할 수 있다. 결과에 fixture임을 표시하고
실제 모델 시험과 분리한다. 테스트 명령의 exit code와 로그를 저장한다.
실제 실행 전 작성한 계획상의 “예상 결과”는 테스트 결과 파일에 넣지 않는다.

## 실제 통합 시나리오

S1: 모델 준비 → COUNT 예제 대화 → 출처 확인 → 강의 계획 → 실제 음성 → 판서·아바타 재생.
S2: 재생 중 “NULL은 왜 빼?” 입력 → 즉시 재생 중단 → 현재 표 유지 → 관련 재설명 → 원강의 복귀.
S3: 학습 시작 중 새로운 채팅 요청 → GPU 경합 정책에 따라 대기/거절 → 학습 취소와 checkpoint 상태 확인.
S4: 사진 업로드 → 잘못 읽은 숫자 수정 → 확정 → 수정한 원문으로 강의 시작.
S5: 서버 재시작 → 기존 대화/학습 기록 유지 → 고아 작업 interrupted → 정상 새 작업 실행.
S6: TTS 미설치·모델 파일 없음·OOM·잘린 문제 → 실제 장애 표시, 그럴듯한 가짜 결과 없음.

실제 통합이 안 되는 환경에서는 같은 renderer fixture 테스트를 수행할 수 있으나 S1~S6 성공으로 대신하지 않는다.

## 보안 기본값

- 127.0.0.1 바인딩, 개발 서버도 외부 노출 기본 금지.
- 관리자 조작은 인증과 CSRF/Origin 검사를 거친다. 임의 웹사이트에서 로컬 API로 학습·삭제를 못 시키게 한다.
- 최초 실행에서 로컬 관리 비밀을 생성하고 본인에게만 전달하는 흐름을 구현한다.
  비밀은 Git/로그/스크린샷/릴리스 ZIP에 넣지 않는다. 영구 비밀을 URL query에 노출하지 않는다.
- 개발 모드라도 인증 우회 옵션이 자동 켜지지 않는다. 일반 UI와 API 모두 권한 검사한다.
- CORS를 무조건 *로 열지 않는다. WebSocket도 Origin·세션을 확인한다.
- HTML/Markdown·KaTeX·SVG 출력은 제한하고 sanitizer를 적용한다. 모델 생성 JS를 실행하지 않는다.
- 업로드에 크기·개수·파일 형식·디코딩 제한, 안전한 파일명, root 경로 검사.
- 임의 경로 읽기/삭제, arbitrary command 실행, 외부 URL fetch, 임의 pip install을 앱 API로 제공하지 않는다.
- 모델/어댑터 업로드는 허용한 안전 형식과 메타데이터를 검사한다. 알 수 없는 pickle을 로딩하지 않는다.
- RAG 문서나 사용자 질문이 시스템 권한·shell·파일 경로를 결정할 수 없게 한다.
- 로그는 오류·job ID 중심으로 기록하고 비밀·전체 문서 원문을 불필요하게 복제하지 않는다.
- 교재·대화·사진은 로컬에만 보관한다. 외부 분석·에러 추적·광고·텔레메트리 업로드는 기본 off.

## 품질의 별도 기준

보안 테스트 통과는 전문가 교육 정확도를 보장하지 않는다.
데모 문제의 정답률과 설명 평가를 각각 기록하고, 불일치하는 경우 그대로 드러낸다.
학습 전보다 나빠진 항목을 숨기거나 자동 평가 규칙을 느슨하게 바꿔 성능을 올려 보이지 않는다.
실제 문제의 정답을 테스트 fixture에서 읽어 모델 응답처럼 보여주는 우회는 금지한다.

# 실행·릴리스·재개 문서

## 사용자에게 제공할 실행 경로

실제로 구현한 CLI 이름과 README를 일치시킨다. 다음은 요구 인터페이스다.
- `python -m edu_tutor doctor`
- `python -m edu_tutor serve`
- `python -m edu_tutor baseline --config configs/local_8gb.yaml`
- `python -m edu_tutor data validate --dataset <경로>`
- `python -m edu_tutor train --smoke --config configs/local_8gb.yaml`
- `python -m edu_tutor train --profile demo --config configs/local_8gb.yaml`
- `python -m edu_tutor evaluate --run <run_id>`
- `python -m edu_tutor jobs list`
- `python -m edu_tutor jobs cancel --id <job_id>`

대규모 학습을 실행하는 명령은 명시적 config·budget을 요구한다.
학습은 웹 관리자와 CLI 모두 같은 validation/lease/job 코드를 사용한다.
serve를 실행할 때 자동 학습·모델 세 개 동시 다운로드가 시작되면 안 된다.

Windows PowerShell과 WSL/Linux의 검증된 실행 안내를 분리한다.
가능하면 `scripts/start.ps1`, `scripts/start.sh`, `scripts/check.ps1`, `scripts/check.sh`를 제공한다.
해당 OS를 실제 테스트하지 못했다면 unverified로 표시한다. 경로 공백·한글·가상환경 활성화 문제를 고려한다.
Windows에서 WSL을 자동 설치하거나 강제 재부팅하지 않는다.
설치 스크립트는 무엇을 설치할지 미리 표시하고 프로젝트 밖 전역 패키지를 바꾸지 않는다.

첫 실행은 ①환경 검사 ②모델 설치 상태 ③서버 기동 ④주소/관리 인증 안내로 진행한다.
브라우저를 못 열면 정상 localhost 주소를 표시한다. 실행되지 않은 주소를 정상 서비스처럼 보고하지 않는다.

## 문서 산출물

README.md: 초보자가 따라 할 설치/실행/종료/학습/오류 안내.
AGENTS.md: 기존 지침을 보존하고 이번 프로젝트의 핵심 규칙을 짧게 병합.
STATUS.json: 단계별 구현/검증/증거/차단 이유.
HANDOFF.md: 실제 현재 상태·마지막 성공 명령·다음 작업과 명령.
docs/ARCHITECTURE.md: 모듈/worker/GPU lease/데이터 흐름.
docs/DATA_GUIDE.md: source/권리/review/split/평가 누수 방지.
docs/TRAINING_GUIDE.md: 가중치·어댑터·실행과 학습·smoke와 본 학습 차이.
docs/OPERATIONS.md: 큐/모델 교체/취소/복구/저장 공간/백업.
docs/LIMITATIONS.md: 실측 성능·미검증 기능·사진/음성/작은 모델 한계.
docs/ACCEPTANCE.md: 테스트 매트릭스의 증거 링크.
docs/DECISIONS.md: 기술 선택·버전·fallback·범위 변경의 이유.
THIRD_PARTY_NOTICES.md: 사용하는 라이브러리·모델·자산의 라이선스와 출처.

README의 숫자나 스크린샷에 샘플 데이터가 있으면 샘플이라고 표시한다.
문서를 작성할 때 테스트를 하지 않았는데 “성공”이라는 기본 템플릿 문구를 남기지 않는다.

## 백업·배포

사용자 PC용 소스 release 묶음을 만든다. venv, node_modules, 대형 모델 가중치,
개인 대화·업로드·auth secret·임시 로그는 기본 제외한다. 필요한 dependency lockfile은 포함한다.
자료와 모델은 사용자가 선택하는 별도 백업 경로로 관리한다.
SQLite는 실행 중 DB 파일을 무작정 복사하지 말고 일관된 backup 절차를 구현한다.
다른 사용자의 PC에서 CUDA가 자동으로 정상 동작한다고 보장하지 않는다.
원격 push/공개 게시/패키지 출판은 요청되지 않았으므로 하지 않는다.

## HANDOFF에 반드시 남길 내용

- 프로젝트 위치와 Git 변경 요약(무단 commit/push를 완료 근거로 사용하지 않음).
- 읽어야 할 현재 지침과 결정 기록.
- 마지막 통과 단계와 실제 test artifact.
- 진행 중 단계, 파일별 다음 수정 사항.
- CPU/GPU/비전/TTS의 검증 여부와 환경 차이.
- 현재 blocker, 재시도 횟수와 원인.
- 사용자가 재개할 정확한 한 줄 지시와 바로 다음 실행 명령.

세션 재개 지시 예:
“STATUS.json과 HANDOFF.md를 읽고 원래 통합 명세를 유지한 채 미완료 단계부터 재개해라.
이미 검증한 코드를 무조건 다시 만들지 말고, 변경된 범위의 테스트를 먼저 확인해라.”

## 최종 보고 양식

프로젝트 상태: LOCAL_MVP_VERIFIED / IMPLEMENTED_RUNTIME_BLOCKED / PARTIAL.
실행 방법: 실제 작동한 명령과 환경.

개발 에이전트는 직접 구현한 결과만 근거로 보고해야 한다.

# 기존 AGENTS.md에 병합할 핵심 지침 예시

이 파일을 프로젝트 루트 AGENTS.md에 그대로 덮어쓰지 않는다. 기존 지침과 충돌 여부를 확인해 병합한다.

- 제품: 개인용 한국어 AI 강사. 로컬 LLM·실제 LoRA 학습·채팅/관리자·판서/음성/아바타를 연결한다.
- 기준 하드웨어: i7-13700F, RAM 32GB, RTX 3060 Ti 전용 8GB.
- 문서는 한국어. 타입·오류 처리·테스트를 포함하고 기존 사용자 변경을 보존한다.
- 단계별 구현/검증은 STATUS.json, 결정은 docs/DECISIONS.md, 중단 지점은 HANDOFF.md에 기록한다.
- 가중치 변경/저장/재로딩을 직접 확인하지 않았으면 실제 학습 성공이라고 하지 않는다.
- CPU fixture pass를 GPU 모델 검증으로 대체하지 않는다. 미실행은 명시한다.
- GPU 작업은 하나의 공통 lease를 사용하고, 학습·채팅·음성·비전을 무조건 동시에 로딩하지 않는다.
- 승인된 자동 예산 안에서만 실행한다. 유료 API·외부 업로드·무한 학습·운영체제 변경은 하지 않는다.
- 데이터 family 누수, 미확정 사진 풀이, 임의 SQL/HTML/코드 실행, 가짜 출처를 차단한다.
- 다음 단계 진행 여부를 매번 묻지 말고 게이트 통과 후 이어간다. 세션 한계를 우회하지 않는다.
- 명령/스크린샷/로그는 실제 실행 증거로만 보고한다.
- tests와 scripts의 실제 경로가 정해지면 아래에 검증 명령을 추가하고 직접 실행한다.
